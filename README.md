# BS

Unity 6 (6000.3) 2D 뱀서라이크. 생존자 4명 대 보스 1명의 비대칭 멀티플레이.

이 프로젝트는 동방 Project의 팬 2차창작을 목표로 하는 비공식 개인 프로젝트다. 원작 게임의 소재(이미지, 음악 등)는 사용하지 않는다.

현재 구현 범위는 네트워크 연결 뼈대(`add-network-skeleton`)와 몹 시뮬레이션/동기화(`add-mob-simulation`)까지다. 전투, 투사체, 레벨업, 보스 스킬과 소환은 아직 없다.

## 구조

- 서버 권한형 리슨 서버(호스트-클라이언트), Netcode for GameObjects
- Relay 방: Unity Multiplayer Services (접속 코드로 참가). 직접 IP 모드는 로컬 테스트용
- 한 방 최대 5명: 보스 1 + 생존자 슬롯 1~4. 역할은 서버의 `RoleTable`이 배정
- 이동: 소유자가 입력을 서버로 보내고, 서버가 위치를 계산해 복제. 소유자는 같은 규칙으로 먼저 움직이고 서버와 어긋나면 보정
- 카메라: 각 클라이언트가 자기 캐릭터만 따라가며 아레나(32 x 20 유닛) 밖은 보이지 않음
- 몹: 서버(호스트)만 시뮬레이션하고 클라이언트는 받은 위치를 보간해서 그린다 (아래 "몹")

```
Assets/Scripts/
  Network/  SessionBootstrap, RoleTable, ArenaConfig, ArenaVisual, DevArgs
  Player/   PlayerAvatar, PlayerRegistry
  Camera/   CameraFollow
  Mobs/     MobSim, MobCodec, MobInterpolator (순수 C#)
            MobServer, MobClient, MobView, MobMessages, MobConfig
  UI/       NetworkMenu (IMGUI 테스트 메뉴)
  Editor/   NetworkSceneSetup (BS > Setup Network Scene)
Assets/Tests/EditMode/   EditMode 테스트 (몹 시뮬레이션, 코덱, 보간기)
tools/                   로그 비교 스크립트
```

## 몹

```
 [서버(호스트)]                                   [클라이언트]
  MobSim (순수 데이터, GameObject 없음)            MobInterpolator (몹별 샘플 버퍼, 약 130ms 지연)
   - 가장자리 스폰, 가장 가까운 생존자 직선 추적        |
   - 격자 해시로 겹침 분리, 아레나 경계               v
        |                                          MobView (풀링된 임시 네모)
        +-- 스냅샷 15Hz, 비신뢰, 몹당 7바이트, 청크당 최대 120마리 -->
        +-- 스폰/제거 이벤트 (신뢰) ------------------------------->
        +-- 접속 시 전체 상태 (신뢰) ------------------------------>
```

- 몹 수: 설계 목표 80, 하드 상한 100 (`MobConfig`). 이동 속도, 스폰율, 반지름도 같은 곳의 상수이며 플레이로 조절한다.
- 보스 지목에 쓸 타겟 변경 지점이 서버에 있다 (`MobSim.SetTarget`, `SetTargetPosition`, `ClearTarget`). 아직 호출하는 곳은 없다.
- 호스트는 메시지를 받지 않고 `MobSim`을 직접 그린다. 그래서 클라이언트는 호스트보다 약 130ms 늦게 본다.
- 생존자의 "살아 있음"은 체력이 생길 때까지 항상 참이다.

## 실행 방법

1. Unity 6000.3으로 프로젝트를 열고 `Assets/Scenes/SampleScene`을 연다.
2. 씬이 비어 있으면 메뉴 `BS > Setup Network Scene`을 실행한다 (여러 번 실행해도 안전).
3. 플레이 모드에서 왼쪽 위 메뉴를 쓴다.
   - **Host**: Relay 방을 만들고 접속 코드를 표시. "보스로 시작"을 켜면 호스트가 보스
   - **Join**: 접속 코드를 입력해 참가
   - **Host (직접) / Join (직접)**: Unity 서비스 없이 같은 PC/LAN에서 테스트
4. 이동은 WASD 또는 방향키. 호스트가 생존자로 시작하면 주변으로 몹이 모여든다.

Relay를 쓰려면 Unity 계정으로 로그인하고 프로젝트가 Unity 클라우드 프로젝트에 연결돼 있어야 한다.

## 테스트

- EditMode 테스트 46개: `Window > General > Test Runner > EditMode`에서 실행한다. 몹 시뮬레이션, 스냅샷/이벤트 부호화(청크 크기 포함), 클라이언트 보간(스냅샷 유실, 무응답 제거, 임시 몹 등)을 다룬다.
- 네트워크 통합 테스트는 아래 실행 인자로 개발 빌드 여러 개를 띄워서 로그로 확인한다.

## 여러 명으로 테스트하기

개발 빌드(Development Build)와 에디터에서만 다음 실행 인자가 동작한다.

| 인자 | 동작 |
|---|---|
| `-bsHost [boss]` | 직접 IP 호스트로 시작 (`boss`를 주면 보스) |
| `-bsHostRelay [boss]` | Relay 호스트로 시작. 접속 코드가 로그에 `relay room code XXXXXX`로 남음 |
| `-bsJoin <ip>` | 직접 IP로 참가 |
| `-bsJoinCode <코드>` | Relay 접속 코드로 참가 |
| `-bsMove <x> <y>` | 고정 이동 입력 |
| `-bsLog` | 1초마다 캐릭터/카메라 위치 로그 |
| `-bsDisplaceAt <초>` | 소유자 위치를 5유닛 밀어 서버 보정을 확인 |
| `-bsMobTarget <n>` | 자동 스폰 목표 몹 수 (하드 상한 100으로 제한) |
| `-bsMobLog` | 5초마다 몹 수, 대역폭, 틱 시간 로그 (서버/클라이언트) |
| `-bsMobDump` | 5초마다 몹 전체 위치 로그 (서버는 보낸 상태, 클라이언트는 화면에 보이는 위치) |
| `-bsMobChurn <초>` | 호스트가 지정한 간격으로 몹을 하나씩 지워 제거 이벤트를 시험 (전투가 생기기 전의 대용) |
| `-bsMobDropEvents` | 클라이언트가 스폰/제거 이벤트를 무시해 임시 몹과 무응답 제거를 시험 |
| `-bsQuit <초>` | 지정 시간 후 종료 |

예: 호스트 하나와 클라이언트를 직접 IP로 띄워 몹 100마리를 만들고 위치를 비교한다.

```
BS.exe -batchmode -nographics -logFile host.log -bsHost -bsMobTarget 100 -bsMobLog -bsMobDump -bsQuit 85
BS.exe -batchmode -nographics -logFile c1.log -bsJoin 127.0.0.1 -bsMobLog -bsMobDump -bsMove 1 0 -bsQuit 70
python tools/compare_mobdumps.py host.log c1.log
```

에디터에서 `F9`는 소유자 위치를 강제로 밀어 보정 동작을 확인하는 디버그 키다.

## 측정 결과

몹 100마리(하드 상한)에서 Relay로 호스트 1 + 클라이언트 4가 접속한 상태를 60초 이상 측정했다. 호스트와 클라이언트는 같은 PC에서 개발 빌드(`-batchmode -nographics`)로 돌렸고 트래픽은 실제 Relay 서버를 거친다.

| 항목 | 결과 | 기준 |
|---|---|---|
| 클라이언트당 몹 트래픽 (페이로드) | 10.37 KB/s | 50 KB/s 이하 |
| 호스트 업로드 (클라이언트 4명 합계) | 약 41.5 KB/s | |
| 클라이언트가 받은 스냅샷 | 초당 15.0회 (유실 관측 없음) | 15Hz |
| 서버 시뮬+전송 시간 (틱당) | 평균 0.085ms, 최대 약 0.5ms | |
| 정상 운영 중 무응답 제거 | 0회 | 0 |
| 서버와 클라이언트의 몹 수/위치 | 5초마다 비교한 모든 지점에서 일치 (같은 시점 기준 차이 0.001 이하) | 0.5유닛 이내 |
| 중간 접속 | 접속 후 0.15초 안에 현재 몹 전체 표시 | 1초 이내 |
| 방 종료 | 클라이언트 4명 모두 몹 100마리를 0으로 정리 | |

측정 방법과 한계:

- 트래픽은 우리가 보낸 메시지의 **페이로드 크기** 기준이다. 전송 계층과 Relay의 패킷 헤더는 포함하지 않았다.
- 시뮬+전송 시간은 몹 100마리에 대한 `FixedUpdate` 한 번의 비용이다. 50Hz에서 코어 하나의 약 0.4%에 해당한다.
- 호스트 프로세스 CPU는 코어 하나의 약 115%로 측정됐지만 **대표값이 아니다**. 헤드리스 빌드는 프레임 제한이 없어 프레임당 0.1ms(초당 약 9000프레임)로 돌기 때문이다. 화면과 프레임 제한이 있는 실제 호스트의 CPU는 따로 측정해야 한다.
- 클라이언트 프레임 시간(평균 약 0.1ms)도 헤드리스 값이라 실제 렌더링 비용을 포함하지 않는다.
- 호스트와 클라이언트가 같은 PC라서 지연이 낮다. 지연이 큰 환경에서의 보간 품질은 측정하지 않았다.
- 위치 비교는 "클라이언트 화면 위치가 서버 상태와 같은 시점에서 일치하는가"를 본다. 화면은 의도적으로 약 130ms 늦다.

## 알려진 한계

- 호스트가 나가면 방이 끝난다 (호스트 이전 없음). 클라이언트는 접속 화면으로 돌아간다.
- 호스트 플레이어는 지연이 없어 약간 유리하다. 보스 밸런스 단계에서 다시 평가한다.
- 소유자 보정 임계값(`PlayerAvatar.correctionThreshold`, 기본 2.5유닛)은 이동 속도 6유닛/초에서 약 400ms 지연까지 평소엔 보정이 일어나지 않도록 잡은 값이다. Relay로 측정했을 때 소유자와 서버의 차이는 최대 약 1유닛이었다. 지연이 더 큰 환경에서는 올려야 할 수 있다.
- 완전한 롤백 예측은 없다. 조작된 위치 주장은 서버 값으로 되돌려진다.
- 테스트 메뉴는 IMGUI이고 정식 로비 UI와 Steam 연동은 범위 밖이다.
- 몹은 한 종류(직선 추적)이고 서로 겹쳐 뭉치는 정도는 분리만 하며 장애물 회피는 없다. 몹이 생존자 위에 모여 덩어리가 된다. 전투가 생기면 해소된다.
- 몹 수가 하드 상한(100)을 넘으면 청크 분할은 지원하지만 대역폭과 호스트 CPU는 다시 측정해야 한다.
