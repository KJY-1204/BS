# Design

## Context

`add-skill-effect-sync` 이후 이 change가 의존하는 현재 구조는 다음과 같다(코드로 확인).

- 서버는 스킬을 쓰는 순간 `SkillCatalog.RangeScalePercent`/`DurationScalePercent`로 퍼센트 정수 배율을 정한다. 값은 시전 캐릭터가 가진 해당 종류 패시브(`PassiveEffectKind.SkillRange`/`SkillDuration`)의 `랭크 x 랭크당 값` 합이고 `clamp(round(100 x (1 + 합)), 100, 250)`이다. `SkillSim.TryActivate`가 반지름, 길이, 폭, 밀어내는 거리에 범위 배율을, 지속(`BuffSeconds`)에 지속 배율을 곱하고, `GrowthServer`가 같은 배율을 스킬 이벤트의 두 바이트에 싣는다. 클라이언트는 `SkillEffectSize`로 같은 곱셈을 한다.
- 마리사의 마스터 스파크는 길이 12(세 랭크 모두), 반폭 0.6/0.7/0.8, 아레나는 폭 32 x 높이 20이다. 광선은 아레나 가장자리에서 잘린다(서버 판정은 몹 위치로, 클라이언트 그림은 `ClipToArena`). 마리사의 스타더스트는 지속 4/5/6초만 있고 범위가 없다.
- 사쿠야의 시간 정지는 지속 2.0/2.5/3.0초(`BuffSeconds`로 `MobSim.Freeze`)이고 범위가 없다. 나이프 난사는 개수(12/16/20)와 피해만 있다. 지속 배율은 시간 정지의 서버 판정에 쓰이고, 몹 위치는 서버 스냅샷으로 가므로 클라이언트에서는 몹이 멈춰 있는 시간으로 자연스럽게 보인다(클라이언트가 시간 정지 시간을 따로 계산하지 않는다).
- 전용 패시브는 `SkillDef`(`Character`, `Passive`, `PassivePerRank`, `RequiresSkill`/`RequiresRank`)로 정의하고, 선택지 규칙(`IsAvailable`)이 소유와 선행 조건과 최대 랭크를 처리한다. 랭크 포장은 3비트 x 번호 1~21이고 번호 19, 20, 21은 아직 쓰이지 않는다.

동기는 proposal.md 참고.

## Goals / Non-Goals

**Goals:**
- 마리사와 사쿠야의 전용 패시브를 하나씩 더해 네 캐릭터가 모두 둘씩 갖게 하고, 지난 change의 배율 기반이 레이무와 사나에 밖에서도 맞는지 확인한다.
- 새 규칙, 새 메시지, 이벤트 형식 변경이 없다.
- 패시브가 없을 때 기존 동작은 달라지지 않는다.

**Non-Goals:**
- 스타더스트의 지속이나 나이프 난사에 닿는 패시브.
- 성장 곡선(레벨 상한, 경험치)과 전체 트리, 균형 정리.
- 시간 정지의 시간을 클라이언트가 따로 그리기.

## Decisions

### 1. 패시브 둘: 극대 마력(범위), 시간 지배(지속)
`SkillCatalog`에 번호 19, 20의 `SkillDef` 둘을 더한다(`IsActive = false`, `Character` 설정, `MaxRank = 3`):

| 번호 | 이름 | 캐릭터 | 효과 종류 | 랭크당 | 선행 |
|---|---|---|---|---|---|
| 19 | 극대 마력 | 마리사 | 스킬 범위 +15% | 15% | 마스터 스파크 1 |
| 20 | 시간 지배 | 사쿠야 | 스킬 지속 +15% | 15% | 시간 정지 1 |

- 마리사는 범위를 고른 이유: 마스터 스파크의 길이와 폭이 효과의 핵심이고 화면에서 바로 보인다. 랭크 3에서 길이 12 -> 17.4, 폭 1.6 -> 약 2.3으로, 아레나 폭 32 안에서 의미가 있다. 지속(스타더스트)은 이번에 다른 캐릭터와 대칭을 맞추기 위해 뺐다. 스타더스트는 마리사의 공격을 빠르게 하는 스킬이라 지속 패시브 후보로 다음 change에서 따로 본다.
- 사쿠야는 지속을 고른 이유: 시간 정지의 시간이 효과의 핵심이다. 랭크 3에서 3.0초 -> 약 4.35초. 쿨타임 20초 대비 얼어 있는 시간 비중이 15%에서 약 22%로 늘어 균형 점검 대상이다(값은 가정값, 시간 감각(쿨타임 -8%/랭크)과 함께 쓰면 더 커진다).
- 값 15%는 사나에의 넓은 바람(15%)과 같게 했고, 모두 가정값이다. 이름과 값은 `SkillCatalog`에서만 정해진다.
- 새 상수 `CritMagicRangePerRank = 0.15f`(극대 마력), `TimeRuleDurationPerRank = 0.15f`(시간 지배)를 기존 패시브 상수 옆에 둔다.
- 대안: 마리사에 지속(스타더스트), 사쿠야에 범위(나이프 난사의 반경 등)를 준다. 사쿠야에는 범위 값이 있는 스킬이 없고, 마리사는 광선이 더 직관적이라 지금 배치가 가장 작다.

### 2. 코드 변경은 카탈로그뿐이다
배율 계산(`PassiveTotal`)은 캐릭터가 가진 해당 종류 패시브를 모두 더하므로 새 정의만 더하면 서버 판정, 이벤트, 클라이언트 그림이 모두 따라온다. `SkillSim.TryActivate`는 마스터 스파크의 `Length`와 `HalfWidth`에 범위 배율을, 시간 정지의 `Duration`에 지속 배율을 이미 곱한다(코드로 확인). 따라서 이 change는 데이터와 시험, 눈 확인이 중심이다.
- 클라이언트의 광선 그림은 `ClipToArena`로 아레나 가장자리에서 자른다. 서버 판정은 몹 위치가 아레나 안에만 있으므로 같은 결과가 된다.

### 3. 기존 시험의 가정 갱신
`CharacterPassiveTests`의 "마리사와 사쿠야는 전용 패시브가 하나"(`OnlyReimuAndSanaeHaveASecondOwnPassive`)를 "네 캐릭터가 모두 둘"로, 다른 캐릭터의 범위/지속 패시브 무영향을 확인하는 시험(`OtherCharactersAreNotAffectedByTheTwoPassives`)을 새 패시브까지 포함하도록 고친다. 마리사에 범위 패시브가 생기므로 "마리사는 범위 배율이 100"이라고 가정한 부분(`ScalesIgnoreOtherCharactersAndOtherKindsOfPassive`)을 새 규칙에 맞게 바꾼다.

### 4. 시험 방법
- 순수 C#: 정의(소유, 효과 종류, 선행, 최대 랭크), 배율 계산(마리사 범위 115/130/145, 사쿠야 지속 115/130/145, 다른 캐릭터와 다른 종류 무영향), `SkillSim`(광선 길이/폭과 시간 정지의 `BuffSeconds`가 배율대로, 스타더스트와 나이프 난사는 무변화), 서버 효과(배율을 키운 광선이 정의된 길이 밖의 몹을 맞춘다, 시간 정지가 배율만큼 몹을 세운다), 선택지 규칙(선행 스킬 전에는 안 나옴, 다른 캐릭터에게 안 나옴).
- 통합: `-bsDevSkills 3 -bsDevPassive 3`으로 서버 로그의 `rangeScale`(마리사 145)과 `durationScale`(사쿠야 145)이 나오는지, 서버와 클라이언트의 이벤트와 배율이 일치하는지, 패시브 없이는 100인지 본다.
- 화면: 개발 빌드를 창 모드로 띄워 프레임 캡처로 광선의 길이와 폭, 몹이 멈춰 있는 시간을 패시브 유무로 비교한다(지난 change의 방법).

## Risks / Trade-offs

- [시간 정지가 너무 강해짐] → 쿨타임 20초에 4.35초면 사쿠야가 몹을 거의 1/4 시간 멈춘다. 값은 `SkillCatalog` 한곳의 가정값이고 균형은 플레이로 정한다. 시간 감각(쿨타임 -8%)과 겹치는 효과를 README 한계에 적는다.
- [극대 마력이 마스터 스파크에만 닿아 약함] → 의도다. 마리사의 다른 스킬(스타더스트 지속)은 다음 change의 후보다.
- [기존 시험이 새 패시브 수를 가정] → 위 3번대로 고치고, 전체 시험 통과로 확인한다.
- [선택지 풀이 커져 한 판의 9번 선택 중 전용 패시브가 차지하는 비율이 커짐] → 선행 조건(Q 스킬 먼저)이 있어서 초반에는 나오지 않는다. 전체 성장 곡선은 다음 change에서 본다.

## Migration Plan

- 저장 데이터와 새 메시지가 없다. 스킬 정의 둘이 더해질 뿐이고 이벤트 형식과 랭크 포장은 그대로다. 씬 설정은 필요 없다. 개발 빌드는 다시 만든다.
- 되돌리기: 새 정의 둘을 카탈로그에서 빼면 이전 동작이다.

## Open Questions

- 스타더스트(마리사 E)의 지속 패시브와 나이프 난사(사쿠야 E)에 닿는 패시브는 다음 change에서 정한다.
- 시간 정지가 길어졌을 때 화면에 지속을 표시할지(예: 몹 위의 얼음 표시)는 균형 점검 때 본다.
