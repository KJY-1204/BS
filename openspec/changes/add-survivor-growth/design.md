# Design

## Context

Change 3까지 서버 전투 시뮬레이션이 있다: `CombatServer`(실행 순서 -50)가 `SurvivorSim`, `AttackSim`, `ProjectileSim`을 돌리고, 투사체의 명중과 종료를 `CombatCodec` 이벤트로 `CombatClient`에 보낸다. 동기와 범위는 proposal.md를, 요구사항은 새 spec 3개와 기존 spec 추가분을 따른다.

현재 코드에서 확인한 것:
- `ProjectileSim.Damage`와 `AttackSim.CooldownSeconds`, `SurvivorSim.MaxHealth`는 모두 전체 공통 값이다. 생존자별 값이 필요하다.
- `PlayerCombat`은 체력(`ushort`, 모두에게)과 부활 게이지(`byte`, 모두에게)를 `NetworkVariable`로 복제하고 최대 체력은 상수(`CombatConfig`)다. HUD와 체력바가 그 상수를 쓴다.
- 몹 처치는 `ProjectileSim`이 만드는 `Hit` 이벤트(`Killed`, 명중 위치)로 알 수 있다. `MobSim`에는 범위 피해가 없다.
- `CombatServer.RegisterSurvivor`/`UnregisterSurvivor`가 생존자 등록의 단일 지점이고, 방이 끝나면 `ResetAll`이 모든 상태를 비운다.
- `CombatCodec`의 이벤트는 종류별 크기가 고정이고 알 수 없는 종류는 읽기에서 거절된다. 클라이언트는 몹과 같은 표시 시계(`MobInterpolator.RenderTime`)로 투사체를 재생한다.
- 소유자 입력은 `PlayerCombat`이 읽고 `[Rpc(SendTo.Server)]`로 보낸다.

## Goals / Non-Goals

**Goals:**
- 성장 규칙(경험치 나눔, 레벨, 선택지 큐, 마나, 스킬 판정)을 순수 C#으로 만들어 EditMode로 검증한다.
- 스킬 하나가 "서버 판정 + 이벤트 복제 + 표시 시계에 맞춘 연출"로 동작하는 틀을 확정해 Change 5가 모양만 채우게 한다.
- 비공개 정보(선택지, 랭크, 경험치, 마나)는 소유자에게만 보낸다.
- 성장이 전투 트래픽 예산(클라이언트당 10 KB/s)을 넘기지 않는다.

**Non-Goals:**
- 캐릭터별 성장표와 스킬, 대기방과 캐릭터 선택, 보스, 에셋.
- 이동 속도 성장(소유자 예측 이동과 보정 임계값을 건드려야 해서 뺀다).
- 범위 폭발로 다친 몹의 체력바(처치된 몹은 사라지는 것으로 충분하다).
- 지연 보상, 스킬 입력 예측.

## Decisions

**1. 데이터: `GrowthConfig`(상수)와 `SkillCatalog`(정적 표)**
스킬은 id(byte), 이름, 패시브/액티브, 슬롯(Q=0, E=1), 최대 랭크, 선행 조건(스킬 id와 랭크), 랭크별 값으로 정의하는 순수 C# 표다. 선택 규칙은 표의 내용을 모르고 `IsAvailable(ranks, skill)`만 쓴다. ScriptableObject 대신 정적 표로 둬서 EditMode 테스트가 쉽고 서버와 클라이언트가 같은 빌드에서 같은 값을 쓴다. Change 5가 캐릭터별 표를 같은 형식으로 추가한다.

**2. 임시 스킬 6개**
패시브 4개(최대 랭크 5): 힘(피해 +2/랭크), 기민(발사 쿨타임 -8%/랭크), 활력(최대 체력 +15/랭크), 집중(최대 마나 +15, 마나 회복 +1/초 per 랭크). 액티브 2개(최대 랭크 3): 폭발(Q, 반경 2.5/3.0/3.5, 피해 20/30/40, 마나 30, 쿨타임 8초)과 연사(E, 선행 조건 기민 1랭크, 지속 4/5/6초, 발사 쿨타임 배율 0.6/0.5/0.4, 마나 25, 쿨타임 12초). 선행 조건 하나를 일부러 넣어 "스킬트리" 규칙(선행 조건)을 테스트로 검증한다.

**3. 스탯 계산 `StatCalc`**
`Compute(level, ranks)`가 최대 체력, 최대 마나, 마나 회복, 투사체 피해, 발사 쿨타임 배율(패시브분)을 돌려준다. 레벨 성장표는 레벨마다 최대 체력 +10, 최대 마나 +5, 투사체 피해 +1이다. 서버가 레벨이나 랭크가 바뀔 때만 다시 계산해서 `SurvivorSim`, `AttackSim`, `SkillSim`에 적용한다. 임시 연사 효과는 쿨타임 배율에 런타임에 곱한다.

**4. `LevelingSim`(서버, 순수 C#)**
생존자별 레벨, 경험치, 스킬 랭크 배열, 선택 큐(대기 중인 선택 수와 현재 선택 `Offer`)를 가진다. 경험치 지급(`AwardKill`)은 처치 위치와 생존자 목록(위치, 생존 여부)을 받아 거리 안의 살아 있는 생존자 전원에게 같은 양을 준다. 한 번에 여러 레벨이 오르면 레벨업 수만큼 선택을 큐에 쌓는다. 레벨 상한에서는 경험치를 무시한다. 선택지는 가능한 스킬(선행 조건 충족, 최대 랭크 아님) 중 무작위 최대 3개로, 가능한 것이 없으면 선택을 열지 않고 큐에서 버린다. 난수는 주입 가능한 `System.Random`이라 테스트가 시드를 고정한다. 결과는 이벤트 목록(`LevelUp`, `OfferOpened`, `OfferClosed`)으로 서버 연결부에 넘긴다.

**5. 선택 시간 초과와 검증**
`Step(dt)`가 현재 선택의 남은 시간을 줄이고 0이 되면 서버가 선택지 중 하나를 무작위로 골라 적용한다(`OfferClosed`의 `auto` 표시). 선택 id(byte, 생존자별 증가, 0은 무효)를 붙여 늦게 온 요청과 이전 선택에 대한 요청을 걸러낸다. `Pick(clientId, offerId, index)`는 범위, 열린 선택 존재, id 일치, 소유자 일치를 모두 확인하고 한 번만 받는다. 한 선택이 닫히면 다음 선택이 새 제한 시간으로 곧바로 열린다. 사망은 선택에 영향을 주지 않고(경험치 지급만 막힌다), 접속 종료는 그 생존자의 상태를 통째로 버린다.

**6. `SkillSim`(서버, 순수 C#)**
생존자별 마나(float), 슬롯별 쿨타임, 연사 남은 시간을 가진다. `Step(dt)`가 마나를 회복하고 시간을 줄인다. `TryActivate(clientId, slot, alive, ranks)`가 습득 여부, 생존 여부, 쿨타임, 마나를 확인하고 `SkillResult`(Fired, NotLearned, Dead, Cooldown, NoMana)와 발동 정보(스킬 id, 랭크, 반경, 피해, 쿨타임)를 돌려준다. 폭발의 실제 범위 피해는 몹을 아는 서버 연결부가 한다. 사망하면 연사가 끝나고, 같은 요청이 반복돼도 쿨타임이 걸러 낸다. 최대 마나가 오르면 현재 마나는 그대로 둔다.

**7. `MobSim.ApplyAreaDamage(center, radius, damage, deaths)`**
격자 조회를 재사용해 반경 안의 몹을 모은 뒤(제거 중 반복 문제를 피하려고 id를 먼저 수집) 각각 `ApplyDamage`를 부른다. 죽은 몹의 위치를 `deaths`에 담아 돌려주고, 제거 이벤트는 기존 경로로 나간다.

**8. `PlayerAvatar`/`AttackSim`/`ProjectileSim`의 생존자별 수치**
`AttackSim`이 생존자별 피해와 쿨타임 배율을 가진다(`SetModifiers`). 발사할 때 그 시점의 피해를 `ProjectileSim.TryFire(..., damage)`로 넘겨 투사체가 자기 피해를 저장한다(비행 중 레벨업이 이미 날아가는 투사체를 바꾸지 않는다). 기존 시그니처도 남겨서 이전 테스트가 그대로 돈다. `SurvivorSim`은 생존자별 최대 체력(`SetMaxHealth`)을 가지며 현재 체력은 건드리지 않고, 부활은 그 생존자의 최대 체력을 쓴다.

**9. 경험치 위치와 킬 수집**
`CombatServer`가 한 틱의 처치 위치 목록(`KillsThisStep`)을 노출한다. 투사체 처치는 `Hit` 이벤트의 명중 위치(몹 중심에서 0.55 이내)를, 폭발 처치는 몹의 실제 위치를 쓴다. 나눔 거리는 10유닛(한 화면의 가로 약 21유닛의 절반 정도)으로 가정한다.

**10. 서버 연결 `GrowthServer`(실행 순서 -40, 전투 다음)**
같은 `FixedUpdate`에서 `CombatServer`가 끝난 뒤 돈다: 대기 중인 스킬 요청 처리(폭발 피해와 처치 위치 수집), 경험치 지급, `LevelingSim`과 `SkillSim` 진행, 스탯 재계산과 적용, 복제 값 갱신, 소유자에게 RPC 전송, 스킬 이벤트 발행. 폭발이 만든 몹 이벤트는 `MobServer.FlushEvents`로, 스킬 이벤트는 `CombatServer.Publish`(기존 배치 전송을 재사용하는 공개 메서드)로 보내 같은 서버 시각을 쓴다. 생존자 등록과 해제는 `CombatServer.RegisterSurvivor`/`Unregister`에서 `GrowthServer`로 이어서 한 지점으로 유지하고, 방이 끝나면 `ResetAll`에서 같이 비운다.

**11. 복제: `PlayerGrowth`(플레이어 프리팹의 새 `NetworkBehaviour`)**
- 모두가 읽음: 레벨(`byte`). 최대 체력은 `PlayerCombat`에 `NetworkVariable<ushort>`로 추가한다(체력바와 HUD가 그 값을 쓴다).
- 소유자만 읽음(`NetworkVariableReadPermission.Owner`): 경험치(`ushort`), 마나와 최대 마나(`ushort`), 스킬 랭크(`ulong`, 스킬당 4비트로 묶음). 마나는 정수 값이 바뀔 때만 쓴다.
- 소유자에게만 보내는 RPC(`SendTo.Owner`): 선택 열림(선택 id, 선택지 3개, 남은 초), 선택 닫힘(선택 id, 고른 스킬, 자동 여부), 스킬 결과(슬롯, 결과, 쿨타임 초).
- 서버로 보내는 RPC(`SendTo.Server`): 선택(선택 id, 번호), 스킬(슬롯). 서버가 소유자와 값을 검증한다.
쿨타임은 값을 계속 복제하지 않고, 발동 때 "쿨타임 몇 초"를 알려 주면 소유자가 로컬 타이머로 보여 준다.

**12. 스킬 이벤트(`CombatEventKind.Skill`, 8바이트)**
종류 1, 스킬 id 1, 소유 슬롯 1, 위치 4(i16 x2), 랭크 1. `CombatCodec`의 크기 표와 읽기 허용 종류에 추가한다. 지속 시간과 반경은 랭크로 양쪽이 같은 `SkillCatalog`에서 얻는다. 클라이언트는 순수 C# `SkillEffectReplay`에 서버 시각과 함께 쌓고 표시 시계가 그 시각에 닿으면 `DueEffects`로 내보내며, 이미 지난 이벤트는 즉시 낸다(`HitEffect`와 같은 규칙). `CombatView`가 폭발은 확장하는 고리로, 연사는 해당 생존자 주변의 보조 표시로 그린다.

**13. 화면 `GrowthHud`(IMGUI)**
경험치 막대와 레벨, 마나 막대, 스킬 슬롯(Q/E: 이름, 랭크, 쿨타임, 마나 부족 표시), 선택 패널(세 선택지, 남은 시간, 숫자 키 안내)을 그린다. 다른 생존자의 레벨은 `Camera.WorldToScreenPoint`로 캐릭터 위에 글자로 그린다. 선택 패널은 열려 있을 때만 숫자 키 1~3을 소비하고, Q와 E는 항상 스킬로 쓴다. 이동 키(WASD)와 겹치지 않는다.

**14. 가정 값(`GrowthConfig`)**
레벨 상한 10, 처치당 경험치 10, 나눔 거리 10, 레벨 L에서 다음 레벨까지 필요한 경험치 `30 + 20 * (L - 1)`, 기본 최대 마나 100, 마나 회복 5/초, 선택 제한 시간 10초, 선택지 3개. 레벨 성장표는 위 3번. 모두 플레이로 조절한다.

**15. 개발용 실행 인자**
`-bsXpPerKill n`(처치당 경험치), `-bsOfferSeconds s`(선택 제한 시간), `-bsDevXp t n`(호스트: t초에 모든 생존자에게 경험치 n), `-bsAutoPick i d`(소유자: 선택이 열린 뒤 d초에 i번을 고름, i가 0이면 고르지 않음), `-bsAutoSkill q|e s`(소유자: s초마다 해당 키를 누름), `-bsGrowthLog`(레벨, 경험치, 선택, 스킬 결과 로그와 5초 통계). 개발 빌드와 에디터에서만 동작한다.

## Risks / Trade-offs

- [투사체 처치의 경험치 위치가 몹 중심이 아니라 명중 위치] → 오차가 0.55 이내이고 나눔 거리 10에 비해 무시할 수 있다. 테스트로 거리 경계의 영향이 없음을 확인한다.
- [선택 패널이 전투 중에 뜨기 때문에 숫자 키 입력과 이동/발사가 겹침] → 숫자 키는 선택 패널이 열렸을 때만 소비하고 마우스와 이동은 그대로 둔다. 자동 선택이 있어 놓쳐도 진행이 막히지 않는다.
- [소유자 전용 `NetworkVariable`과 RPC가 호스트 본인에게 다르게 동작할 수 있음] → 호스트도 같은 경로(로컬 실행)로 처리되는지 에디터와 개발 빌드에서 확인한다.
- [서버 틱에서 RPC로 알린 선택 결과와 `NetworkVariable`로 복제한 랭크가 어긋나 UI가 깜박임] → 랭크는 `NetworkVariable`만 진실로 쓰고 RPC는 알림 표시용으로만 쓴다.
- [스킬 이벤트가 늘어 전투 트래픽이 예산을 넘음] → 이벤트가 8바이트이고 폭발 쿨타임이 8초라 네 명이 계속 써도 초당 약 1~2개 수준이다. 측정해서 기록한다.
- [레벨이 오르는 속도가 너무 빨라 선택이 쌓임] → 처치당 경험치와 필요 경험치는 상수라 조절하고, 큐와 자동 선택이 쌓여도 진행을 막지 않는다.
- [이전 change의 테스트가 `ProjectileSim.Damage`/`SurvivorSim.MaxHealth`에 기대고 있음] → 기존 시그니처와 기본값을 유지해 그대로 통과시키고, 새 동작은 새 테스트로 덮는다.
- [`PlayerCombat`, 프리팹, 씬 설정 변경이 이전 동작(체력, 부활)을 깰 수 있음] → 기존 EditMode 전체와 이전 통합 로그 비교를 다시 돌려 확인한다.
