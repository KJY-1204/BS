# Proposal

## Why

보스의 소환이 주력이 됐지만 몹은 한 종류뿐이라, 소환은 "같은 몹을 더 부르기"에 그친다. 보스가 상황에 맞는 몹을 골라 부를 수 있어야 소환이 전술이 된다(빠른 몹으로 도망가는 생존자를 압박하고, 단단한 몹으로 길을 막는 식). 지금은 몹의 "출처"(자동, 소환)를 종류 값 하나가 겸하고 있어 종류를 늘릴 수 없으므로, 출처와 종류를 분리하면서 능력치만 다른 몹 종류 3가지를 만든다. 행동이 다른 몹(원거리, 폭발)은 다음 change로 미룬다.

## What Changes

- **몹 종류 3가지(능력치만 다름).** 기본(지금 몹 그대로), 빠른 몹(빠르고 약하며 조금 작다), 단단한 몹(느리고 체력이 많으며 크고 더 세게 닿는다). 모두 같은 방식으로 생존자를 쫓는다. 수치는 모두 기본 몹 값에 대한 배율이고 가정값이다.
- **출처와 종류를 분리한다.** 서버는 몹마다 출처(자동/소환)와 종류를 따로 안다. 와이어 형식은 그대로다: 스폰 이벤트의 종류 바이트 하나에 출처(낮은 비트)와 종류(나머지 비트)를 함께 싣는다. 종류 0 + 자동은 지금과 같은 값(0), 종류 0 + 소환도 지금과 같은 값(1)이다.
- **종류마다 능력치가 다르다.** 이동 속도, 최대 체력(체력 비율 계산 포함), 몸 크기(몹끼리 밀어냄, 투사체 명중, 생존자와 닿는 거리, 아레나 가장자리), 접촉 피해가 종류별 값을 따른다. 생존자가 여러 몹에 닿으면 보호 시간당 한 번이고 그 피해는 닿은 몹 중 가장 센 것이다.
- **자동 스폰은 기본 종류만.** 자동 스폰 몹은 항상 기본 종류이고 자동 목표 수 계산도 그대로다.
- **보스가 소환할 종류를 고른다.** 숫자 키 1/2/3으로 종류를 고르고 Space로 소환한다. 선택은 보스 쪽에 남고 소환 요청과 함께 서버로 간다(서버가 종류를 검증한다). 종류마다 몹 하나의 기운 비용과 한 번에 부르는 몹 수(무리 크기)가 다르다. 기운이 모자라면 살 수 있는 만큼만 만드는 규칙, 거절 규칙, 쿨타임은 종류와 상관없이 그대로다. 명령(생존자 지정, 지점 지정)은 종류와 상관없이 모든 소환 몹에 적용된다.
- **화면.** 몹은 종류별 색과 크기로 그려진다(기본 종류는 지금처럼 출처로 색이 갈린다). 보스 화면의 소환 막대 옆에 종류 목록(키, 이름, 비용)과 선택 표시가 뜬다. 생존자에게는 새 표시가 없고 몹이 다르게 보일 뿐이다.
- **개발 인자.** `-bsAutoSummonKind <종류>`로 자동 소환이 고르는 종류를 정한다(기본 1번 종류). 기존 `-bsMobHealth`, `-bsMobSpeed`는 기본 종류의 값을 바꾸고 다른 종류는 그 배율을 따른다.
- 범위 밖(다음 change): 행동이 다른 몹(원거리 발사, 폭발, 분열), 종류별 처치 경험치 차이, 종류 4개 이상, 보스 스킬, 보스 종류 2종, 자동 소환 장치, 캐릭터별 스킬 트리, 몹 에셋. 몹 처치 경험치는 모든 종류가 같다.

## Capabilities

### New Capabilities
- `mob-kinds`: 몹 종류를 데이터로 정의하고(속도, 체력, 크기, 접촉 피해, 소환 비용과 무리 크기, 이름, 색), 출처와 종류를 분리해 알며, 종류별 능력치가 모든 몹 규칙에 반영되고, 종류가 기존 형식으로 모든 클라이언트에 알려져 종류별 색과 크기로 그려지는 것.
- `summon-kind-selection`: 보스가 소환할 종류를 고르는 입력, 서버의 종류 검증, 종류별 기운 비용과 무리 크기, 보스 화면의 종류 목록과 선택 표시.

### Modified Capabilities
- `mob-simulation`: 쫓는 속도, 서로 밀어냄, 최대 체력, 접촉 피해, 몹의 출처 규칙이 종류별 값과 출처/종류 분리를 반영한다.
- `mob-replication`: 몹이 나타날 때 모든 클라이언트가 종류와 출처를 알게 된다.
- `boss-summoning`: 소환 몹이 "자동 몹과 모든 면에서 같다"는 규칙이 "고른 종류의 몹"으로 바뀌고, 기운 비용이 종류별로 정해지며, 소환 몹의 색 규칙이 출처와 종류를 함께 다룬다.

## Impact

- 코드: 새 순수 C# `Mobs/MobKinds`(종류 데이터, 출처/종류 부호화), `MobSim`(종류별 속도, 체력, 크기 배열, 종류를 받는 스폰, 가장 센 접촉 피해 질의, 몹 크기로 밀어내기와 경계 처리, 출처 질의 유지), `SurvivorSim`(접촉 피해를 종류별로), `SummonSim`(종류 인자, 종류별 비용과 무리 크기, 새 거절 결과 `UnknownKind`), `SummonServer`, `PlayerSummon`(숫자 키 선택, 요청에 종류 실음, 선택 상태 노출), `SummonHud`(종류 목록과 선택 표시), `MobView`(종류별 색과 크기), `DevArgs`가 바뀐다. `MobCodec`/`MobInterpolator`/`MobClient`는 형식이 같아 바뀌지 않는다.
- 네트워크: 새 메시지도, 몹 스냅샷과 이벤트의 형식 변화도 없다. 보스가 서버에 보내는 소환 RPC에 종류 바이트 하나가 더해진다(보스만 보냄, 이벤트는 몹 스폰 이벤트 그대로). 몹 트래픽(50 KB/s 이하)과 전투 트래픽(10 KB/s 이하)을 Relay로 다시 잰다.
- 동작 변화: 기본 종류 몹의 수치와 동작은 이전과 같아야 한다(회귀 시험으로 확인). 소환 키는 Space 하나이고 1/2/3 키가 종류 선택으로 새로 쓰인다. 소환 시 기본 선택은 1번 종류(기본)이므로 키를 안 눌러도 지금과 같다.
- 테스트: 종류 데이터, 부호화, 종류별 이동/체력/밀어냄/명중/접촉 피해, 종류별 소환 비용과 무리 크기와 거절은 순수 C#이라 EditMode로, 보스 + 생존자 여러 프로세스(종류별 소환, 비용, 스탯, 몹 위치 일치, 전투 이벤트 일치, 이전 회귀)와 실제 Relay로 검증한다.
- 저작권: 이 단계도 이름과 임시 색, 도형만 쓴다.
- 이후 change: 행동이 다른 몹, 보스 스킬, 자동 소환 장치.
