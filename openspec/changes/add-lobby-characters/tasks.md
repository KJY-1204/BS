## 3. 서버 연결 (room-lobby, multiplayer-session, player-movement-sync, mob-simulation)

- [x] 3.1 `RoleTable`을 바꾼다: 접속 때는 역할 배정과 슬롯 추가만 하고 스폰하지 않으며, `Phase`(`NetworkVariable`)와 `PlayerSlot.Character`를 복제하고, 선택/시작/판 종료 RPC(보낸 사람 확인, 거절은 보낸 사람에게만 통지)를 두고, 시작할 때 슬롯마다 캐릭터를 스폰하며 `[BS] lobby ...` 로그를 남긴다. 에디터에서 대기방 접속 시 캐릭터가 없고 선택이 슬롯 목록에 반영되며 시작하면 캐릭터가 스폰되는 것을 `eval`과 로그로 확인한다
- [x] 3.2 `PlayerAvatar`가 캐릭터 id를 모두에게 복제하고 서버 이동과 소유자 예측이 같은 캐릭터 이동 속도를 쓰며 색을 캐릭터 색으로 쓰게 한다(보스는 역할 색과 기본 속도). 에디터에서 두 캐릭터의 속도와 색이 다르고 소유자 예측이 서버와 어긋나 보정되지 않는 것을 `eval`로 확인한다
- [x] 3.3 `SessionBootstrap.Approve`가 진행 중이면 사유와 함께 거절하게 하고(정원 검사는 그대로), 캐릭터 등록이 캐릭터 시작 체력과 마나로 이루어지게 `CombatServer.RegisterSurvivor`와 `GrowthServer.Register`를 연결한다(`-bsSurvivorHealth` 보정은 한 곳에서). 승인 거절 사유와 캐릭터별 시작 체력을 단위 시험이 닿는 범위는 EditMode로, 나머지는 로그로 확인한다
- [x] 3.4 판 종료(`EndMatch`)를 구현한다: 모든 캐릭터 despawn, `CombatServer`/`GrowthServer`/`MobServer` 초기화를 공개 메서드로 노출해 서버 정지 경로와 공유, 몹 0마리 전체 상태 전송, `Phase`를 대기로. 클라이언트는 `Phase` 변경에서 몹, 투사체, 스킬 연출, 선택 패널을 비운다. 에디터에서 판 종료 뒤 서버와 화면에 캐릭터, 몹, 투사체가 없고 다시 시작하면 처음과 같은 상태인 것을 `eval`로 확인한다
