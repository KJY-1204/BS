# Design

## Context

`add-network-skeleton`로 서버 권한형 리슨 서버, 역할 슬롯(`RoleTable`), 서버 이동(`PlayerAvatar`), 역할별 카메라가 있다. 동기와 범위는 proposal.md를 따르고, 요구사항은 `mob-simulation`, `mob-replication` spec을 따른다.

현재 코드에서 확인한 것:
- 서버에서 생존자 위치는 `PlayerAvatar`의 서버 위치 값(`serverPos`)과 `transform`으로 얻을 수 있다. 역할은 `PlayerAvatar.Role`(0 = 보스, 1~4 = 생존자)이다.
- 서버/호스트의 이동 계산은 `FixedUpdate`에서 돈다.
- NGO 2.13의 `CustomMessagingManager`(`SendNamedMessage`, `RegisterNamedMessageHandler`)와 `NetworkDelivery`(`UnreliableSequenced`, `ReliableSequenced`, `ReliableFragmentedSequenced`)를 쓸 수 있다.
- 아직 체력과 사망이 없으므로 "살아 있는 생존자"는 현재 모든 생존자다.

## Goals / Non-Goals

**Goals:**
- 몹 100마리까지 5명에게 클라이언트당 약 50 KB/s 이하로 복제한다(`mob-replication`의 대역폭 예산).
- 몹 시뮬레이션이 순수 C# 데이터라서 에디터 테스트로 검증된다.
- 이후 투사체 동기화가 재사용할 메시지 전송 기반(이벤트/스냅샷 송수신)을 만든다.
- 실제 Relay에서 부하(대역폭, 호스트 CPU)를 측정하고 결과를 기록한다.

**Non-Goals:**
- 전투, 체력, 사망, 투사체, 보스 명령과 소환 자원, 몹 종류 다양화.
- 서버 시간과 클라이언트 시간의 정밀 동기화. 보간용 단순 시계 추정으로 충분하다.
- 관심 영역 기반 전송(클라이언트 화면 근처 몹만 보내기). 아레나가 작고 100마리 상한이므로 필요 시 나중에 한다.

## Decisions

**1. 서버 시뮬레이션은 순수 C# `MobSim`**
몹은 구조체 배열(id, 종류, 위치, 속도, 타겟)로 관리하고 GameObject와 Rigidbody를 쓰지 않는다. 겹침 분리는 셀 크기 1.0의 격자 해시에서 3x3 이웃만 검사해 겹친 쌍을 반씩 밀어낸다. 몹 수가 100 이하여서 틱당 비용은 매우 작다. `MonoBehaviour`는 틱 호출과 메시지 전송만 맡고, 로직은 `MonoBehaviour`에 의존하지 않아 EditMode 테스트가 가능하다. 대안인 개별 `NetworkObject`는 생성/삭제 비용과 업로드가 크고 투사체에 재사용이 안 되어 택하지 않는다.

**2. 시뮬레이션 틱은 `FixedUpdate`(50Hz), 스냅샷은 15Hz로 분리**
시뮬은 플레이어 이동과 같은 `FixedUpdate`에서 돌고, 스냅샷은 누적 시간으로 약 1/15초마다 보낸다. 서버는 스냅샷마다 증가하는 틱 번호를 붙인다.

**3. 전송은 NGO 이름 있는 메시지(Custom Messaging)**
- `bs.mob.snap`: 위치 묶음. `UnreliableSequenced`. 오래된 스냅샷은 버려진다.
- `bs.mob.evt`: 스폰과 제거. `ReliableSequenced`.
- `bs.mob.full`: 새 접속자에게 현재 몹 전체(종류와 위치)를 한 번에. `ReliableFragmentedSequenced`.
개별 `NetworkVariable`이나 `NetworkList`는 변경 추적과 직렬화 오버헤드가 커서 쓰지 않는다.

**4. 스냅샷 형식: 몹당 7바이트, 청크 분할**
몹 하나는 id(2, ushort), x(2), y(2), 플래그(1)다. 좌표는 1/1000 유닛 단위의 16비트 정수로 양자화한다(아레나 ±16 x ±10이라 범위에 충분하고 정밀도는 0.001). 청크 헤더에는 틱 번호, 청크 번호/개수, 항목 수를 넣는다. 청크당 최대 120마리(약 850바이트)로 해서 전송 계층의 패킷 한도보다 여유 있게 작게 유지한다. 100마리면 한 청크, 상한을 늘려도 자동 분할된다. 각 청크는 독립적으로 쓸 수 있어 한 청크가 유실돼도 그 몹들만 한 번 건너뛴다.

**5. 클라이언트 보간: 몹별 짧은 샘플 버퍼와 렌더 시계**
각 몹은 최근 3개 정도의 (시간, 위치) 샘플을 가진다. 렌더 시계는 "받은 가장 새 틱 시간 - 약 130ms"를 따라가며 로컬 시간으로 진행하고, 어긋남이 크면 천천히 맞춘다. 두 샘플 사이를 선형 보간하고, 샘플이 부족하면 마지막 위치에 머문다(추측 이동은 하지 않음). 한 스냅샷이 유실돼도 130ms 버퍼 안에서 다음 샘플로 이어져 튀지 않는다. 알 수 없는 id의 위치가 먼저 도착하면 임시로 몹을 만들고 스폰 이벤트나 전체 상태가 도착하면 종류를 갱신한다. 2초 동안 위치가 오지 않은 몹은 제거한다.

**6. 호스트 화면은 시뮬레이션을 직접 읽음**
호스트는 메시지를 받지 않고 `MobSim`의 현재 위치를 그대로 그린다. 호스트 플레이어의 캐릭터가 서버 값을 직접 쓰는 것과 같다. 클라이언트가 약 130ms 늦게 보이는 것과 호스트의 약간의 이점은 알려진 한계로 둔다(skeleton의 리스크와 같다).

**7. 화면은 풀링된 `MobView`**
시작 시 설계 목표 수만큼 스프라이트를 미리 만들고 필요하면 상한까지 늘린다. 몹 화면은 시뮬을 변경하지 않는다. 몹 id가 사라지면 풀로 반환한다. 프레임마다 힙 할당이 생기지 않게 배열을 재사용한다.

**8. 몹 id는 ushort, 순환 증가하며 사용 중인 값은 건너뜀**
슬롯을 바로 재사용하면 늦게 도착한 이벤트가 새 몹에 적용될 수 있어서 증가하는 id를 쓰고, 0은 무효값으로 둔다.

**9. 타겟 변경 지점은 서버 쪽 메서드**
`MobSim`에 `SetTarget(mobId, clientId)`, `SetTargetPosition(mobId, position)`, `ClearTarget(mobId)`를 둔다. 대상 플레이어가 나가면 서버가 자동으로 해제한다. 이번에는 호출하는 곳이 없고 테스트만 있다. 보스 명령이 붙을 때 추가 동기화는 필요 없다.

**10. 생존자 위치 조회는 작은 레지스트리**
서버에서 생존자 아바타를 `PlayerRegistry`(정적 목록)에 등록/해제하고, `MobSim`은 위치 배열만 입력으로 받는다. "살아 있음" 플래그는 지금 항상 참으로 두고 Change 3에서 체력과 연결한다.

**11. 가정(튜닝 상수로 둠)**
몹 이동 속도 2.5 유닛/초(플레이어 6보다 느림), 기본 스폰 2마리/초, 설계 목표 80, 하드 상한 100, 스폰 위치는 아레나 가장자리 안쪽 0.5 지점이며 생존자와 5유닛 이내이면 다른 위치로 다시 고른다. 몹 반지름 0.4. 모두 `MobConfig`의 상수이고 플레이로 조절한다.

**12. 측정 도구**
서버는 보낸 페이로드 바이트(클라이언트당)와 시뮬 틱 시간(평균/최대)을 5초마다 로그로 남긴다. 클라이언트는 받은 바이트와 표시 중인 몹 수, 프레임 시간을 남긴다. `DevArgs`에 `-bsMobLog`(로그)와 `-bsMobTarget N`(설계 목표 덮어쓰기)을 추가한다. "몹 트래픽"은 우리가 보낸 메시지의 페이로드 크기로 정의한다. 전송 계층의 패킷 헤더 오버헤드는 별도로 추정해서 기록한다.

## Risks / Trade-offs

- [페이로드 외에 패킷 헤더와 Relay 오버헤드가 붙어 실제 대역폭이 예산보다 클 수 있음] → 측정 시 페이로드 기준값과 함께 OS 수준 전송량도 한 번 확인한다. 100마리 기준 약 8 KB/s(15Hz x 7B x 100 x 약 0.75)로 예산 50 KB/s에 크게 여유가 있어 위험은 낮다.
- [`UnreliableSequenced`가 전송 계층의 패킷 한도를 넘는 메시지에서 실패] → 청크 크기를 120마리(약 850바이트)로 제한하고, 상한을 키울 때 청크 크기를 유지한다. 테스트로 상한 수에서 검증한다.
- [클라이언트 렌더 시계가 어긋나 몹이 떨리거나 멈춤] → 시계를 천천히 보정하고 어긋남이 클 때만 재설정한다. 로그에 샘플 부족 횟수를 남겨 측정한다.
- [호스트가 시뮬, 렌더, 네트워크, 플레이를 모두 해서 CPU가 부족할 수 있음] → 몹 100마리의 틱 시간이 작을 것으로 예상하지만, 측정해서 기록하고 필요하면 상한을 조절한다.
- [스냅샷 청크가 부분 유실되면 일부 몹만 한 틱 건너뜀] → 몹별 샘플 버퍼와 130ms 지연으로 흡수한다. 유실률이 높은 환경은 범위 밖이다.
- [임시 몹이 스폰 이벤트 없이 만들어진 뒤 이벤트가 영영 안 오는 경우] → 2초 무응답 제거와 전체 상태 메시지가 보완한다.
