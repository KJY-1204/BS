# Proposal

## Why

보스는 지금 1종이다. 보스 플레이어는 대기방에서 아무것도 고르지 못하고, 보스의 기본 공격(`BossAttack`)과 두 스킬(`BossSkills`)은 상수라서 코드 18곳이 직접 읽는다. 생존자는 캐릭터 넷 중에서 고르고 빌드를 짜는데 보스 쪽은 선택이 없어서 4대1 비대칭의 보스 쪽 의사결정이 비어 있다. 보스 종류를 데이터로 만들고, 보스 플레이어가 대기방에서 고르게 하고, 종류마다 다른 수치와 다른 스킬을 주려 한다.

## What Changes

- **보스 종류 데이터**: 보스를 종류 데이터로 정의한다. 종류마다 이름, 최대 체력, 이동 속도, 몸 반지름, 접촉 피해, 색, 기본 공격(피해, 쿨타임, 투사체 모양), Q/E 두 스킬(효과 종류, 쿨타임, 피해, 경고 시간, 효과 값)을 가진다. 지금 보스의 값은 그대로 **표준**(1번)이 되고, **거인**(2번)과 **저격수**(3번)를 더해 모두 세 종류다.
- **다른 수치(2a)**: 거인은 체력이 많고 느리고 크고 접촉 피해가 크다. 저격수는 체력이 적고 빠르고 작고 기본 공격이 빠르다.
- **다른 스킬(2b)**: 새 스킬 효과 둘을 더한다. **광선**(경고선을 보여 준 뒤 보스의 조준 방향 직선 위 생존자를 해친다)과 **포효**(경고 뒤 보스 주위에 몹을 소환한다). 거인은 충격파(Q)와 포효(E), 저격수는 탄막(Q)과 광선(E), 표준은 지금처럼 탄막(Q)과 충격파(E)다.
- **선택(1a)**: 보스 플레이어가 대기방에서 종류를 고른다(생존자의 캐릭터 선택과 같은 방식). 고르지 않으면 표준이다. 판이 시작되면 그 판의 종류가 정해지고 모든 클라이언트가 안다. 판 도중에는 바꿀 수 없다.
- **모두가 같은 보스를 본다**: 이름, 색, 크기, 이동 속도, 기본 공격 쿨타임과 투사체 모양, 스킬 경고(링과 광선), 보스의 스킬 슬롯 표시가 종류에 따라 달라진다. 새 메시지는 대기방의 종류 선택 요청과 판 시작 때의 종류 알림뿐이다.
- 기본 공격과 스킬의 "약해질수록 강해짐"(분노) 규칙은 그대로 두고 값만 종류의 기본 공격 값을 따른다.
- 개발 인자 `-bsBossKind <번호>`로 보스 플레이어의 종류를 자동으로 고른다.

## Capabilities

### New Capabilities
- `boss-kinds`: 보스 종류의 정의(데이터), 기본값, 대기방에서의 선택, 판에 적용되고 모두에게 알려지는 것.

### Modified Capabilities
- `boss-combat`: 보스 정의가 종류별 데이터이고(더는 한 종류가 아님) 기본 공격과 스킬을 포함한다.
- `boss-skills`: 두 스킬이 종류마다 정해지는 효과이고, 광선과 포효가 더해지며 모두에게 보이는 경고가 효과에 맞는다.
- `room-lobby`: 대기방이 보스의 종류 선택도 보여 준다.

## Impact

- 코드: `BossCatalog`/`BossDef`(종류 데이터, 선택), `BossAttack`/`BossSkills`(상수에서 종류 데이터로, 사용처 18곳), `BossSkillSim`(효과 종류별 해제, 광선과 포효), `LobbySim`/`RoleTable`/`PlayerSlot`(보스 종류 선택과 복제), `CombatServer`/`CombatClient`/`CombatView`(종류에 따른 공격 모양과 경고), `PlayerAvatar`/`PlayerCombat`/`PlayerSummon`(속도, 쿨타임, 스킬 슬롯), `MatchHud`/`SummonHud`/`NetworkMenu`(이름, 슬롯, 선택 UI), `DevArgs`.
- 시험: 종류 데이터(표준이 지금 값과 같음), 선택 규칙, 광선과 포효 효과, 종류별 공격과 스킬 EditMode 시험. 보스 상수를 직접 쓰는 기존 시험은 종류 데이터를 거치도록 고친다.
- 네트워크: 대기방의 종류 선택 요청(RPC 1개)과 판 시작 때의 종류 값 하나가 늘고, 보스 스킬 요청에 조준 각도가 실리고, 스킬 경고 번호가 효과별로 늘어난다(200~203). 전투 이벤트 형식은 변하지 않는다.
- 균형: 모든 이름과 값은 가정값이다. 거인과 저격수의 균형은 균형 change에서 본다.
- 호환: 저장 데이터가 없다. 호스트와 클라이언트가 같은 빌드를 써야 하는 지금 전제 그대로다. 표준 보스의 동작은 그대로여서 기존 회귀 시험은 그대로 통과해야 한다.
