# Design

## Context

`add-marisa-sakuya-passives` 이후의 현재 구조(코드로 확인).

- 제한시간은 `BossCatalog`의 `MatchSeconds = 300f` 한 곳에 있고, `-bsMatchSeconds`가 덮어쓴다. 남은 시간은 `MatchSim`이 세고 서버가 클라이언트에 알린다. 시간에 따라 변하는 다른 게임 값은 없다(보스 분노는 체력 기준, 소환 에너지는 연속 회복).
- 성장 상수는 `GrowthConfig`에 있다: `MaxLevel = 10`, `XpPerKill = 10`, `XpNeeded(level) = 30 + 20 x (level - 1)`(레벨 10까지 합계 990), 레벨당 체력 +10, 마나 +5, 피해 +1. 같은 거리 안의 살아 있는 생존자는 몹 하나의 경험치를 각자 전부 받는다(나누지 않는다).
- `LevelingSim`은 `MaxLevel`에서 경험치를 무시하고, 선택지 풀이 비면 레벨업이 선택에 걸리지 않게 `continue`한다. 레벨은 `NetworkVariable<byte>`, 경험치는 `ushort`다.
- 한 캐릭터가 배울 수 있는 랭크: 공통 패시브 4개(힘, 기민, 활력, 집중) x 최대 5 = 20, 전용 Q/E 2 x 3 = 6, 전용 패시브 2 x 3 = 6, 합계 32. 레벨 20이면 선택은 19번이라 풀이 마르지 않는다.
- 랭크 포장은 `ulong` 하나에 3비트 x 번호 1~21(63비트)이다. 코드 주석은 "4비트, 번호 1~16"이라고 적혀 있어 사실과 다르다.

동기는 proposal.md 참고.

## Goals / Non-Goals

**Goals:**
- 판 길이를 15분으로 늘리고, 레벨과 선택 횟수가 판 길이에 맞게 이어지도록 상한과 곡선을 정한다.
- 레벨 9 이하의 동작과 값은 그대로 둔다.
- 새 메시지, 형식 변경 없이 상수와 식만 바꾼다.

**Non-Goals:**
- 스킬/패시브 추가와 랭크 포장 확장(번호 21 넘기기). 다음 change(A-2)에서 정한다.
- 보스 체력, 몹 수, 소환 에너지, 몹 능력의 재조정(균형 change).
- 경험치를 몹 종류별로 다르게 주기, 경험치를 나누기.

## Decisions

### 1. 판 길이 900초, 레벨 상한 20
`MatchSeconds`를 900, `MaxLevel`을 20으로 한다. 상한을 20으로 잡은 이유: 레벨 20이면 선택이 19번이고 풀(32랭크)의 약 60%라서 한 판에 한 캐릭터 트리의 큰 부분을 채우되 전부 채우지는 못한다(빌드 선택이 의미를 가진다). 25는 풀 32랭크에 너무 가까워 선택이 사라진다. 두 값 모두 가정값이다.

### 2. 필요 경험치: 레벨 9까지는 그대로, 이후는 완만하게
```
XpNeeded(l) = 30 + 20 x (l - 1)         (l <= 9)    30, 50, ... 190
XpNeeded(l) = 190 + 10 x (l - 9)        (l >= 10)   200, 210, ... 290 (l = 19)
```
- 레벨 10까지 합계는 990 그대로, 레벨 20까지는 3440(몹 344마리)이다. 같은 킬 속도라면 레벨 20은 레벨 10의 약 3.5배 시간이다. 목표 곡선(5분에 레벨 10, 15분 안쪽에 상한)에 가깝다.
- 기울기를 20에서 10으로 줄인 이유: 20을 유지하면 레벨 19 -> 20이 370이 되어 후반 성장이 멈춰 보인다. 줄이지 않으면 합계가 4,000을 넘는다(약 4배).
- 단조 증가라서 "레벨이 오를수록 줄지 않는다"는 요구를 만족한다.
- 실제 킬 속도는 시간이 갈수록 보스 소환 때문에 오르고 생존자도 강해지므로, 표시한 배수는 어림일 뿐이다. 값은 `GrowthConfig` 한 곳이고 플레이로 조절한다.
- 대안: 로그 곡선이나 표 형식. 식 두 줄이 시험과 조절에 충분하다.

### 3. 자동 성장표는 그대로
레벨당 체력 +10, 마나 +5, 피해 +1을 유지한다. 레벨 20이면 체력 +190, 마나 +95, 피해 +19(기본 10에 비해 약 2.9배)가 된다. 힘 랭크까지 더하면 화력이 크게 늘 수 있어, 보스 체력 6000이 15분 안에 너무 일찍 닳을 위험이 있다. 이번에 값을 만지면 시험 결과의 원인을 가리기 어려워 그대로 두고 위험으로 적는다.

### 4. 코드 변경은 상수, 식, 주석, 표시 확인
- `GrowthConfig.MaxLevel`, `XpNeeded`, `BossCatalog.MatchSeconds`를 바꾼다.
- `SkillCatalog`의 랭크 포장 주석을 사실(3비트, 번호 1~21)에 맞게 고친다.
- HUD의 레벨, 경험치 막대, 남은 시간 표시가 두 자리 레벨과 15:00에서 잘리지 않는지 개발 빌드를 창 모드로 캡처해 확인한다. 문제가 있으면 그 표시만 고친다.

### 5. 시험 방법
- 순수 C#: `XpNeeded` 값과 단조성(레벨 9 이하는 이전 값, 이후는 위 식), 상한 20에서의 경험치 무시, 두 레벨을 한 번에 올려 상한에서 멈추는 경우, 풀이 마른 상태에서의 레벨업(레벨 20까지 선택 19번 안에서 선택지가 비지 않음을 캐릭터별로 확인, 풀 32랭크), 한 판 길이 설정값. 상한 10을 가정한 기존 시험을 고친다.
- 통합: 개발 인자 `-bsDevXp`로 레벨업을 빠르게 만들어 레벨 20까지 도달하고 선택이 매번 열리고 닫히는지, 상한 뒤 경험치가 무시되는지, 둘째 판이 레벨 1로 시작하는지, 15분 설정으로 `-bsMatchSeconds` 없이 시작했을 때 남은 시간이 900에서 시작하는지 본다.
- 실제 Relay: 보스 호스트 + 생존자 3명으로 레벨 20까지 올리며 한 판(제한시간을 줄인 판으로 결과/복귀/둘째 판 포함), 트래픽과 틱 시간을 잰다.

## Risks / Trade-offs

- [보스가 15분 전에 너무 일찍 죽음] -> 보스 체력 6000, 소환 에너지는 5분 판 기준이다. 이번에는 바꾸지 않고 균형 change에서 본다. README 한계에 적는다.
- [레벨 20 화력이 지나치게 큼] -> 자동 성장 +19 피해와 힘 랭크가 겹친다. 위와 같이 균형 대상으로 둔다.
- [곡선 배수가 실제와 다름] -> 목표 곡선은 일정한 킬 속도 가정이다. 값은 한 곳이라 조절이 쉽다.
- [풀 크기와 상한의 균형] -> 선택 19번에 풀 32랭크라 비지 않는다. A-2에서 풀을 키울 때 상한과 다시 맞춘다.

## Migration Plan

- 저장 데이터와 새 메시지가 없다. 상수와 식이 바뀌고 개발 빌드를 다시 만든다. 씬 설정은 필요 없다.
- 되돌리기: 상수와 식을 이전 값으로 되돌린다.

## Open Questions

- 보스 체력과 소환 에너지를 15분 판에 맞춰 다시 정하는 시점(균형 change).
- A-2에서 스킬이 늘면 랭크 포장을 어떻게 넓힐지(비트 수를 늘리거나 포장을 둘로 나누기). 이번 change에서는 정하지 않는다.
