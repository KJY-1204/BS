# Design

## Context

Change 2까지 서버 몹 시뮬레이션(`MobSim`), 스냅샷/이벤트 전송(`MobCodec`, `MobServer`, `MobClient`), 보간기(`MobInterpolator`), 생존자 레지스트리(`PlayerRegistry`)가 있다. 동기와 범위는 proposal.md를 따르고, 요구사항은 새 spec 4개와 `mob-simulation`, `mob-replication`의 추가분을 따른다.

현재 코드에서 확인한 것:
- 서버는 `FixedUpdate`(50Hz)에서 몹을 돌리고 스냅샷은 15Hz로 보낸다. 스냅샷과 몹 이벤트 헤더는 틱 번호(u32)를 싣고, 클라이언트는 `tick / 15`를 서버 시각으로 쓴다.
- 클라이언트 화면은 서버보다 약 130ms 늦다(`MobInterpolator`의 렌더 시계). 호스트는 시뮬레이션을 직접 그린다.
- `MobSim`은 격자 해시를 `Separate()` 안에서만 만들고 몹이 2마리 미만이면 건너뛴다. 몹에 체력이 없고 `Remove(id)`가 제거 이벤트를 만든다.
- `PlayerAvatar`는 이동 입력만 서버로 보내고(`SetInputRpc`), 체력이나 죽음 개념이 없다. `PlayerRegistry.CollectSurvivors`는 `Alive`를 항상 참으로 채운다.
- 클라이언트 시계는 보간기 안에 있고, 제거 이벤트는 받는 즉시 적용된다.

## Goals / Non-Goals

**Goals:**
- 공격 한 발이 서버 판정과 이벤트 재생으로 모든 화면에서 같은 시각에 보이게 한다.
- 투사체, 피해, 체력, 부활 규칙을 순수 C#으로 만들어 EditMode 테스트로 검증한다.
- 투사체 위치를 보내지 않고 이벤트만으로 전투 트래픽을 클라이언트당 10 KB/s 이하로 유지한다.
- 이후 캐릭터별 공격(모양만 다른 이벤트)과 보스 피해가 이 구조 위에 쌓이게 한다.

**Non-Goals:**
- 지연 보상(서버가 플레이어 화면 시각으로 몹 위치를 되감아 판정). 아래 위험에 적었다.
- 소유자 쪽 투사체 예측(클릭 즉시 투사체 표시). 연출용 총구 섬광만 즉시 보여 준다.
- 경험치, 마나, 스킬, 캐릭터별 공격, 보스 피해, 전멸 처리.

## Decisions

**1. 서버 시각 기준 통일: 이벤트 헤더는 밀리초, 스냅샷은 틱을 유지**
서버 시각을 `(snapshotTick + accumulator / interval) / 15`초로 정의한다. 스냅샷 틱 k는 정확히 `k/15`초이고, 그 사이의 이벤트는 같은 시간선 위의 연속 값이다. 몹 이벤트와 전투 이벤트 헤더는 이 값을 밀리초(u32)로 싣는다. 스냅샷 형식은 바꾸지 않아 기존 비교 도구와 로그를 그대로 쓴다. 대안인 모든 메시지를 밀리초로 바꾸는 방식은 스냅샷 덤프 비교 방식을 다시 설계해야 해서 택하지 않는다.

**2. 몹 제거는 서버 시각에 맞춰 적용**
`MobInterpolator.OnRemove(id, serverTime)`는 렌더 시계가 그 시각에 도달할 때까지 몹을 남겨 둔다. 이미 지났거나 시계가 없으면 즉시 제거한다. 이렇게 해야 투사체가 도착하는 순간에 몹이 사라진다. 지연된 제거 후에도 늦게 온 스냅샷이 되살리지 않도록 기존 묘비(tombstone) 규칙은 실제 제거 시점부터 적용한다.

**3. 공격은 `AttackSim`, 투사체는 `ProjectileSim` (서버, 순수 C#)**
`AttackSim`은 생존자별 조준 각도, 발사 여부, 남은 쿨타임을 가진다. 쿨타임은 버튼을 뗀 뒤에도 계속 줄어들고 0 아래로는 내려가지 않아서, 눌렀다 뗐다 하는 방식으로 속도를 올릴 수 없다. 틱마다 최대 한 발을 쏘고, 첫 발은 눌렀을 때 바로 나간다. `ProjectileSim`은 고정 크기 배열(상한 256)에 위치, 방향, 남은 수명, 소유자를 둔다. 틱마다 선분 `[이전 위치, 이동한 위치]`을 `MobSim`의 선분 조회로 검사해 가장 가까운 몹을 맞힌다(빠른 투사체의 통과 방지). 아레나 경계에 닿거나 수명이 끝나면 사라진다.

**4. `MobSim`에 체력, 피해, 접촉 조회 추가**
몹 체력 배열과 `ApplyDamage(id, damage, out hpPercent, out killed)`를 둔다. 0이 되면 `Remove`로 제거하고 기존 제거 이벤트가 나간다. 격자 해시는 `Step` 끝(이동과 경계 보정 이후)에 항상 다시 만들어서 선분/원 조회가 최신 위치를 쓴다. 조회는 `TryHitSegment(a, b, radius, out id, out point)`와 `AnyWithin(center, radius)`이다.

**5. 생존자 상태는 `SurvivorSim`(체력, 무적, 접촉 피해, 부활)**
서버 쪽 순수 C# 클래스가 생존자별 체력, 남은 무적 시간, 부활 게이지를 관리한다. 입력은 생존자 목록(위치, 살아 있는지, 지금 움직이는지)과 `MobSim`이다. 접촉 판정은 몹이 있는 원(생존자 반지름 + 몹 반지름)으로 보고, 무적 시간 동안은 피해가 없다. 부활은 죽은 생존자마다 범위 안에서 멈춰 서 있는 살아 있는 생존자가 있으면 게이지를 채우고, 아니면 0으로 되돌린다. 구조체 상태를 `PlayerCombat`의 `NetworkVariable`로 반영한다.

**6. 서버 오케스트레이션은 `CombatServer`(실행 순서 -50), 몹은 `MobServer`(-100)**
같은 `FixedUpdate`에서 몹이 먼저 움직이고(격자 갱신 포함) 그다음 전투가 돈다. `CombatServer`는 생존자 목록 수집, `SurvivorSim.Step`, `AttackSim.Step`, `ProjectileSim.Step`, 결과를 `NetworkVariable`과 이벤트로 내보내기를 순서대로 한다. 보스 역할의 아바타는 공격하지 않으며 체력도 없다.

**7. 입력과 전송: `PlayerCombat`(소유자 입력, 서버 RPC)**
`PlayerCombat`은 플레이어 프리팹의 새 `NetworkBehaviour`다. 소유자는 마우스 위치(카메라로 월드 변환 후 자기 캐릭터 기준 방향) 또는 오른쪽 스틱으로 각도를 구하고, 발사 버튼을 읽는다. 각도는 16비트로 양자화해서 `(angle, firing)`을 서버 RPC로 보낸다. 발사 상태가 바뀌거나 각도가 1도 이상 바뀌고 50ms 이상 지났을 때만 보낸다(초당 20회 상한). 서버는 마지막으로 받은 값을 쓴다. 입력 처리와 검증(각도 범위, 죽었는지, 보스인지)은 서버에서 한다.

**8. 전투 이벤트는 새 메시지 `bs.atk.evt`(신뢰, 순서 보장)**
`MobMessages`와 같은 방식이다. 배치 헤더는 서버 시각(ms, u32)과 개수, 항목은 세 종류다.
- 발사: kind, 투사체 id(u16), 소유 슬롯(u8), 시작 위치(i16 x2), 각도(u16)
- 명중: kind, 투사체 id, 몹 id, 남은 체력 퍼센트(u8), 처치 여부(u8), 위치(i16 x2)
- 종료(맞히지 못함): kind, 투사체 id, 위치(i16 x2)
속도, 수명, 반지름은 `CombatConfig` 상수로 양쪽이 같은 값을 쓴다(빌드가 같아야 함). 한 틱의 이벤트를 하나의 배치로 보낸다. 중간 접속자에게는 투사체 기록을 보내지 않는다(곧 사라지는 연출이라서).

**9. 클라이언트 재생: `ProjectileReplay`(순수 C#)와 `ProjectileView`**
발사 이벤트로 투사체를 만들고, 렌더 시계 `t`에서 위치를 `origin + dir * speed * (t - startTime)`으로 계산한다. `t`가 시작 시각 전이면 아직 안 보인다. 명중/종료 이벤트는 끝 시각과 끝 위치를 저장하고, `t`가 그 시각에 도달하면 끝 위치에서 멈추고 사라진다. 이벤트가 없어도 수명과 여유 시간이 지나면 제거한다. 몹과 같은 렌더 시계를 쓰기 때문에 투사체가 도착하는 순간에 몹이 사라진다. 호스트는 보간 없이 서버 값으로 직접 그린다. 풀링한 스프라이트를 쓰고 프레임당 할당이 없게 한다.

**10. 맞은 몹의 체력바는 클라이언트 연출**
명중 이벤트의 남은 체력 퍼센트로 해당 몹 위에 약 1.5초 동안 작은 막대를 보여 준다. 몹이 사라지면 같이 사라진다. 체력은 몹 스냅샷에 넣지 않는다.

**11. 생존자 체력과 부활 게이지는 `NetworkVariable`**
`PlayerCombat`이 `NetworkVariable<ushort>`(체력)과 `NetworkVariable<byte>`(부활 게이지 퍼센트, 죽었을 때만 의미)를 복제한다. 서버만 쓰고 모두가 읽는다. 값이 바뀔 때만 쓴다. 죽은 상태는 체력 0으로 판단한다. 체력바와 부활 게이지는 아바타 자식 스프라이트이고, 로컬 체력은 IMGUI 표시로 보여 준다.

**12. 소유자 연출용 총구 섬광**
클릭 입력과 로컬 쿨타임 추정이 맞으면 소유자 화면에서 캐릭터에 작은 섬광만 즉시 보여 준다. 투사체와 피해는 서버 결과를 따른다. 서버 왕복과 표시 시계 지연(약 130ms) 때문에 투사체는 입력 후 약 0.2초 뒤에 보이므로, 이 섬광이 반응성을 보완한다.

**13. 죽은 생존자 처리**
죽으면 서버가 이동 입력과 발사를 무시한다. 소유자 쪽 예측 이동도 죽으면 멈춘다. 몹은 `SurvivorInfo.Alive`로 타겟에서 제외한다. 이동 중 죽었다면 서버의 현재 위치에서 멈춘다.

**14. 가정(튜닝 상수 `CombatConfig`)**
생존자 체력 100, 접촉 피해 10, 무적 0.6초, 생존자 반지름 0.5. 몹 체력 30(`MobConfig`). 투사체 피해 10(몹 3발), 쿨타임 0.25초, 속도 14 유닛/초, 수명 0.9초(사거리 약 12.6), 반지름 0.15, 상한 256. 부활 범위 1.5, 부활 시간 4초, 부활 체력 50%, 부활 후 무적 2초. 체력바 표시 1.5초. 부활 중 공격은 게이지를 초기화하지 않고 움직임만 초기화한다. 여러 명이 동시에 부활시켜도 속도는 같다. 모두 플레이로 조절한다.

**15. 개발용 실행 인자**
조준과 발사를 자동화하는 `-bsAim x y`, `-bsFire`, `-bsAimSweep 도/초`, 전투 통계 로그 `-bsCombatLog`, 시나리오 `-bsDevKill 역할 시각`(해당 역할 생존자를 죽임), `-bsDevMeet 역할A 역할B 시각`(A를 B 옆으로 이동)을 둔다. 개발 빌드와 에디터에서만 동작한다.

## Risks / Trade-offs

- [화면의 몹은 서버보다 약 130ms 늦어서, 클라이언트가 보이는 몹을 조준해 쏘면 움직이는 몹을 빗맞힐 수 있음] → 몹 이동 속도(2.5)로 약 0.33유닛의 오차가 생기지만 몹 반지름 0.4 + 투사체 0.15 안이라 대부분 맞는다. 지연 보상은 이번 범위 밖이고, 체감이 나쁘면 후속 change에서 서버가 발사 시각의 표시 시각으로 몹 위치를 되감아 판정한다.
- [투사체가 입력 후 약 0.2초 뒤에 보임] → 소유자 총구 섬광으로 보완하고, 투사체 즉시 표시(예측)는 후속 과제로 둔다.
- [몹 제거를 시각에 맞춰 늦추면 이미 죽은 몹이 130ms 동안 화면에 남아 접촉 피해 등과 어긋나 보일 수 있음] → 이 지연은 몹 표시 전반의 지연과 같으므로 일관되게 받아들인다.
- [투사체 이벤트가 많아 대역폭이 커질 수 있음] → 발사 10B, 명중 11B 수준이라 4명이 초당 4발씩 쏘면 약 1 KB/s로 예상한다. 예산은 10 KB/s이고 측정해서 기록한다.
- [서버에서 몹 선분 조회 비용] → 격자 이웃 칸만 검사하고 투사체 상한 256, 몹 100이라 작다. 틱 시간을 측정한다.
- [죽은 생존자 위치에 몹이 모여도 그대로 둠] → 몹은 살아 있는 생존자를 쫓으므로 죽은 생존자 위의 몹은 흩어진다. 부활 시점에 몹이 겹쳐 있으면 무적 시간 2초로 흡수한다.
- [몹 제거 시각 적용이 이벤트 지연으로 느려지면 `MobInterpolator`의 묘비/무응답 제거와 충돌] → 지연 제거 대기 중인 몹은 무응답 제거 대상에서 제외하고 EditMode 테스트로 확인한다.
- [`PlayerAvatar`와 프리팹 변경으로 이전 change의 이동 동작이 깨질 수 있음] → 기존 이동 테스트와 통합 로그 비교를 다시 돌려 확인한다.
