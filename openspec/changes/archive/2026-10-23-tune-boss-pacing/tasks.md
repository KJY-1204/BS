# Tasks

## 1. 보스 체력 복제의 폭 (boss-combat)

- [x] 1.1 `PlayerCombat`의 복제되는 `health`와 `maxHealth`를 `NetworkVariable<int>`로 넓히고 `ServerWrite`가 `int` 범위로 자르게 한다(초기값과 형변환 정리). 서버와 클라이언트가 읽는 속성(`Health`, `MaxHealth`)과 HUD는 그대로 둔다. 개발 빌드를 호스트 보스(`-bsBossHealth 250000`) + 생존자 3명으로 돌려, 클라이언트 로그의 `[BS] health owner=... role=0 ... -> ...`에 250000과 그 아래 값이 잘리지 않고 나오고(예: 250000 -> 249985), 보스 체력 줄(HUD 캡처)이 `250000 / 250000`으로 보이며, 늦게 들어온 클라이언트도 같은 값을 읽는 것을 확인한다. 생존자 체력 복제(체력 줄, 부활 게이지)가 이전과 같은 것은 기존 EditMode와 다중 프로세스 전투 비교(`compare_combat.py`)로 확인한다

## 2. 하네스에 스킬별 덮어쓰기 (도구)

- [x] 2.1 `HarnessOverrides`에 `bossSkillQDamage`와 `bossSkillEDamage`를 더한다(그 판 보스 복사본의 첫째/둘째 스킬 피해만 바꿈, 카탈로그는 그대로). EditMode 테스트로 두 이름이 알려진 이름이고, 하나만 바꾸면 다른 스킬과 카탈로그가 그대로인 것, 모르는 이름의 거절 메시지에 새 이름이 나오는 것을 확인한다

## 3. 값 찾기 (하네스)

- [x] 3.1 표준, 거인, 저격수 각각 설정 파일(덮어쓰기만)로 설계의 시작값 근처를 훑는다: 속도 ±0.5, 체력 ±25%, 저격수는 기본공격 3~6과 빔 20~30. 종류마다 normal 40판, weak와 strong 각 40판을 돌리고, 수락 기준(normal 승률 35~70%, 판 길이 중앙값 480~840초, 보스가 반 체력에 닿는 판 50% 이상)을 만족하는 값을 고른다. 선택한 값에 속도 10% 빠르게와 체력 20% 많게를 돌려 고원의 폭을 보고, 고원 가운데에 있는지 확인해 값을 조정한다. 결과 표(종류별 값, normal/weak/strong의 승률, 판 길이, 반 체력 시각, 쓰러짐)와 설정 파일을 `tools/harness/pacing-*.json`과 요약으로 남긴다. 수락 기준을 못 맞추는 종류가 있으면 멈추고 어떤 값이 안 되는지 보고한다
- [x] 3.2 고른 값을 `BossCatalog`에 쓴다(세 종류의 `MaxHealth`와 `MoveSpeed`, 저격수의 `BaseDamage`와 빔 `Damage`). "표준 종류는 예전 보스의 값"이라는 주석과 문서를 새 말로 고친다. 3.1에서 쓴 설정 파일의 값으로 하네스를 덮어쓰기 없이 다시 돌려 같은 결과(같은 시드는 같은 줄)가 나오는 것을 확인한다

## 4. 시험 (boss-kinds)

- [x] 4.1 기존 보스 종류 시험을 새 값으로 바꾼다: 표준이 예전 보스와 같다는 확인을 지우고, 종류별 속도 확인(`BossKindTests`의 6, 4.5, 8)과 기본값 확인(`BossDataTests`의 6)을 새 값으로 바꾼다. 종류별 체력이 생존자 기본 공격이 1초에 주는 피해의 1000배 이상인 것, 모든 종류의 속도가 모든 생존자 캐릭터보다 느린 것, 거인 < 표준 < 저격수의 순서, 거인이 체력과 접촉 피해가 표준보다 크고 저격수가 체력이 표준보다 작고 기본 공격이 더 빠른 것을 데이터 시험으로 확인한다. 이어서 하네스 세션에서 생존자가 곧장 멀어지고 보스가 곧장 따라가는 판을 모든 종류와 모든 캐릭터로 돌려 간격이 계속 벌어지는 것을 확인한다
- [x] 4.2 보스 종류와 보스 공격/스킬, 접촉 피해, 복제, 하네스를 다루는 기존 EditMode 테스트 전체가 새 값으로 통과하는 것을 확인한다(값을 직접 박은 시험은 값만 새 것으로 고치고 규칙은 그대로)

## 5. 통합 확인과 문서

- [x] 5.1 (통합) 직접 IP 다중 프로세스로 보스 종류마다 한 판씩(`-bsBossKind 1/2/3`, 보스 호스트 + 생존자 3명)을 돌려, 서버와 클라이언트의 몹 위치와 전투 이벤트가 일치하고, 보스 이동이 서버 로그의 속도와 맞고(느려진 보스가 생존자보다 느림), 보스 체력 줄이 큰 체력에서 맞게 줄어드는 것(HUD 캡처)과 늦게 들어온 클라이언트가 같은 체력을 읽는 것을 확인한다. 보스 승패 세 가지(처치, 전멸, 시간 종료)와 소환·명령·장치·성장 시나리오가 이전과 같은 모양인지 본다. 실제 Relay로 한 판을 끝까지 하며 클라이언트당 트래픽(몹 50 KB/s, 전투 10 KB/s 이하)과 서버 틱 시간을 측정한다
- [x] 5.2 (화면 확인) 개발 빌드를 창 모드로 띄워 보스 체력 숫자와 줄이 큰 값에서 맞게 보이는지, 느려진 보스가 어색하게 보이지 않는지(생존자가 앞서 나감) 눈으로 확인한다. 어긋나면 그 표시만 고친다
- [x] 5.3 기존 EditMode 테스트 전체를 다시 돌려 통과를 확인하고, README를 고친다(보스 종류 표의 새 값, "표준 종류는 예전 보스" 문구 삭제, `-bsBossHealth` 한계 문구 삭제, 하네스 덮어쓰기에 새 이름, 새 측정 결과: 종류별 정확한 값과 normal/weak/strong 결과와 고원 폭, 알려진 한계: 값은 봇 기준이라 사람이 하면 쉬울 수 있고 직접 해 본 뒤 후속 조정이 필요할 수 있다). 문서의 하네스 명령을 그대로 따라 해서 재현되는지 확인한다
