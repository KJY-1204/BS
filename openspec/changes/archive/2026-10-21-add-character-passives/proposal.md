# Proposal

## Why

생존자 네 명은 기본 공격과 Q/E 스킬은 서로 다르지만, 레벨업에서 고르는 패시브(힘, 기민, 활력, 집중)는 네 명이 똑같다. 그래서 레벨업 선택이 캐릭터의 개성으로 이어지지 않고, 캐릭터를 고르는 재미가 시작 수치와 스킬 둘에서 끝난다. 보스 쪽(공격, 소환, 몹 5종, 스킬 둘)에 비해 생존자 쪽 깊이도 얕다. 캐릭터마다 전용 패시브를 하나씩 더해 레벨업 선택지가 캐릭터별로 달라지게 한다. 전체 트리는 크므로 이번에는 한 개씩으로 작게 시작하고, 값을 보며 나중에 늘린다.

## What Changes

- **캐릭터마다 전용 패시브 하나.** 기존 공통 패시브 4개는 그대로이고, 각 캐릭터는 자기 것만 레벨업 선택지에 나오는 전용 패시브를 하나 더 갖는다. 이미 있는 "스킬은 한 캐릭터 소유일 수 있다" 규칙과 선택 규칙을 그대로 쓰므로 선택 방식, 복제, 선택 패널은 바뀌지 않는다.
  - 레이무 「영력 절약」: 스킬의 마나 소모가 랭크마다 10% 줄어든다.
  - 마리사 「화력 제일」: 자기 스킬의 피해와 회복량이 랭크마다 15% 늘어난다(마리사의 마스터 스파크).
  - 사쿠야 「시간 감각」: 스킬의 쿨타임이 랭크마다 8% 줄어든다.
  - 사나에 「신앙」: 마나 회복이 랭크마다 초당 1.5 늘어난다.
- **전용 패시브는 자기 첫 스킬을 배운 뒤에 나온다.** 효과를 받을 스킬이 없으면 낭비이므로 각 전용 패시브는 그 캐릭터의 Q 스킬이 랭크 1이 된 뒤에 선택지에 나온다(기존 선행 조건 규칙). 최대 랭크는 3이다.
- **효과는 서버가 계산한다.** 마나 소모, 피해/회복량, 쿨타임은 스킬을 쓰는 순간 서버가 전용 패시브 랭크로 계산하고, 마나 회복은 기존 스탯 계산(`StatCalc`)에 더한다. 클라이언트에는 새 값이 가지 않는다. 클라이언트의 스킬 슬롯 표시(마나 부족 표시, 쿨타임 막대)는 소유자 자신이 아는 랭크로 같은 계산을 해서 서버와 맞춘다.
- **랭크 포장 확장.** 스킬 번호 13~16이 새로 필요해서, 랭크 포장(소유자에게만 가는 값)의 번호 한도를 15에서 16으로 늘린다(번호 1부터 시작하도록 자리를 한 칸씩 당김). 새 네트워크 값이나 메시지는 없다.
- **새 개발 인자는 없다.** 기존 `-bsDevSkills`, `-bsAutoPick` 등으로 시험한다. 선택지 목록은 서버 로그에 이미 나온다.
- 범위 밖(다음 change): 캐릭터마다 선택지 여러 개(전체 트리), 새 서버 규칙이 필요한 복잡한 패시브(관통 수, 투사체 수, 이동 속도 성장 등), 효과 크기를 키우는 패시브(범위, 지속 시간 - 클라이언트 효과 그림이 어긋남), 보스 종류 2종, 자동 소환 장치, 유도 투사체, 에셋, 점수.

## Capabilities

### New Capabilities
- `character-passives`: 캐릭터별 전용 패시브(네 가지)의 정의, 누가 어떤 패시브를 선택지로 받는지, 선행 조건과 랭크, 서버가 계산하는 효과(마나 소모, 피해와 회복량, 쿨타임, 마나 회복), 소유자 화면의 표시.

### Modified Capabilities
- `skill-tree-selection`: 패시브가 모두 공통이라는 규칙이 "공통 패시브와 캐릭터 전용 패시브"로 바뀐다.
- `survivor-mana-skills`: 스킬의 마나 소모, 쿨타임, 피해가 전용 패시브 랭크로 달라질 수 있다.
- `survivor-leveling`: 레벨과 스킬로 정해지는 스탯(마나 회복)에 전용 패시브가 더해진다.

## Impact

- 코드: `SkillCatalog`(전용 패시브 정의 네 개, 패시브 효과 종류와 랭크당 값, 효과 계산 함수, 번호 한도와 랭크 포장 자리), `SkillDef`(패시브 효과 필드), `SkillSim`(마나 소모, 쿨타임, 피해/회복량에 전용 패시브 반영), `StatCalc`(마나 회복에 전용 패시브 반영), `GrowthHud`(슬롯의 마나 비용과 쿨타임 표시를 실제 값으로)가 바뀐다. `LevelingSim`, `GrowthServer`, `PlayerGrowth`, 네트워크 형식은 바뀌지 않는다.
- 네트워크: 새 메시지와 새 이벤트 형식이 없다. 소유자에게만 가는 랭크 포장 값의 자리 배치만 바뀐다(같은 빌드끼리만 접속한다는 전제).
- 동작 변화: 기존 캐릭터의 공통 패시브, 스킬, 선택 규칙은 그대로다. 레벨업 선택지 풀에 전용 패시브 하나가 추가되므로 선택지 구성이 달라질 수 있다.
- 테스트: 정의, 선택지 규칙(소유, 선행 조건, 최대 랭크), 효과 계산(마나 소모, 피해/회복량, 쿨타임, 마나 회복), 랭크 포장은 순수 C#이라 EditMode로, 보스 + 생존자 여러 프로세스(캐릭터별 선택지와 전용 패시브 선택과 효과, 이벤트 일치, 이전 회귀)와 실제 Relay로 검증한다.
- 저작권: 이 단계도 이름과 임시 색, 도형만 쓴다.
- 이후 change: 전체 트리, 더 복잡한 패시브, 보스 종류 2종.
