# Design

## Context

동기와 범위는 proposal.md를, 요구사항은 새 spec 2개(`boss-combat`, `match-outcome`)와 기존 spec 변경분을 따른다.

현재 코드에서 확인한 것:
- 보스는 `RoleTable.BossRole`(0)로 대기방에 들어오고 판이 시작되면 스폰되지만, 생존자 전용 시스템(`CombatServer.RegisterSurvivor`, `GrowthServer`, 체력 막대, HUD)이 모두 보스를 건너뛴다. 보스 이동 속도는 `CharacterCatalog.BossMoveSpeed` 상수 하나다.
- `PlayerCombat`의 체력은 `NetworkVariable`(현재, 최대)이고 막대는 생존자에게만 그려진다. 서버가 `ServerWrite`로 값을 채운다.
- `ProjectileSim.Step`은 투사체마다 `MobSim.CollectSegmentHits`로 맞은 몹을 모아 순서대로 피해를 준다. 이벤트의 `MobId`는 `ushort`이고 몹 식별자는 `MobSim`이 1부터 순환하며 만든다(0은 쓰지 않는다).
- 스킬은 `SkillExecutor.Apply(활성화, SkillContext)`가 효과별로 `MobSim`, `ProjectileSim`, `SurvivorSim`을 만진다.
- `SurvivorSim.ApplyContactDamage`는 몹이 반경 안에 있고 몹이 멈춰 있지 않으면 접촉 피해를 준다. 몹이 얼면 접촉 피해가 사라진다(시간 정지).
- 방 상태는 `LobbySim`(대기, 진행)과 `RoleTable`의 `NetworkVariable<byte> Phase`다. 판 종료(`EndMatch`)는 모든 캐릭터를 despawn하고 `CombatServer`, `GrowthServer`, `MobServer`를 초기화한 뒤 `Phase`를 대기로 바꾼다. `PhaseChanged` 이벤트를 클라이언트의 몹, 전투 표시가 구독한다.
- 시뮬레이션은 모두 `FixedUpdate`(50Hz)에서 도는 서버 컴포넌트들(`MobServer` -100, `CombatServer` -50, `GrowthServer` -40)이다. 정지시킬 일관된 한 곳은 없고 각자 `running` 검사를 한다.

## Goals / Non-Goals

**Goals:**
- 보스 피해와 승패 규칙을 순수 C#(`BossSim`, `MatchSim`)에 두고 EditMode로 검증한다.
- 승패가 나면 판의 모든 진행이 한꺼번에 멈추게 하는 단일 스위치를 둔다.
- 결과 상태에서 기존 "판 종료 → 대기방" 정리 경로를 그대로 재사용한다.
- 새 메시지 없이 기존 전투 이벤트와 복제 값만 쓴다.

**Non-Goals:**
- 보스의 몹 소환, 목표 지정, 자동 소환 장치, 보스 종류와 스킬, 체력 비례 강화(다음 change).
- 보스 부활, 보스 전용 에셋, 점수, 관전, 재접속.
- 보스의 공격 판정 방식 변경(접촉 피해만).

## Decisions

### 1. 보스는 몹도 생존자도 아닌 별도 `BossSim`(순수 C#)의 대상이다
`BossSim`이 보스 체력, 위치, 반지름, 쓰러짐을 가진다. 몹과 달리 한 마리뿐이고 이동은 플레이어가 하므로(서버가 `PlayerAvatar` 위치를 매 틱 넘겨 준다) 시뮬레이션은 위치를 받아 판정만 한다. `TakeDamage(int)`는 쓰러졌으면 무시하고 체력이 0 아래로 내려가지 않게 하며, 쓰러지는 순간에 한 번 `JustFell`을 올린다.
- 대안: 보스를 `MobSim`의 특별한 몹으로 → 몹은 서버가 움직이고 목록으로 복제하는 구조라, 플레이어가 조종하는 보스와 어긋난다. 채택하지 않았다.
- 대안: 생존자처럼 `SurvivorSim`에 등록 → 부활, 접촉 피해 받기 같은 규칙이 다르다. 채택하지 않았다.

### 2. 보스 정의는 코드 안의 표(`BossCatalog`)로 둔다
`CharacterCatalog`와 같은 방식이다. 가정값(플레이로 조절):

| 항목 | 값 | 설명 |
|---|---|---|
| 최대 체력 | 6000 | 생존자 4명이 레벨 1~4로 약 3분 사격해야 쓰러지는 양을 노린 값(레이무 6/s x 기본 피해 10 x 0.6 등으로 4명 합계 약 70~100 피해/초) |
| 이동 속도 | 6.0 | 지금 보스 속도 |
| 반지름 | 0.9 | 몹(0.4)의 두 배 이상 |
| 접촉 피해 | 25 | 몹의 10보다 크다 |
| 색 | 빨강 | 지금 역할 색 |
| 제한 시간 | 300초 | 5분 |

이름은 임시("보스"). 캐릭터가 정해지면 `Name`만 바꾼다.

### 3. 보스 명중은 기존 `Hit` 이벤트에 예약된 몹 식별자로 싣는다
`CombatCodec`의 `Hit`은 몹 식별자 `ushort`를 싣는다. 보스를 가리키는 값으로 `ushort.MaxValue`(65535)를 예약하고(`BossSim.MobId`), `MobSim.NextFreeId`가 그 값을 건너뛴다(spec의 `mob-simulation`). 그러면 이벤트 형식, 복제 경로, `ProjectileReplay`의 관통 규칙이 그대로다. 클라이언트의 명중 효과는 그 식별자면 몹 막대 대신 보스 체력 막대를 갱신한다. 보스의 체력 비율은 이벤트의 기존 `MobHealthPercent`에 싣는다.
- 대안: 새 이벤트 종류 → 코덱, 테스트, 클라이언트 모두 손봐야 하고 이득이 없다. 채택하지 않았다.

### 4. `ProjectileSim`이 보스를 후보에 합친다
`ProjectileSim.Step`이 한 틱의 선분에서 `MobSim.CollectSegmentHits`로 몹 후보를 모으고, 보스가 있고 살아 있으면 같은 방식(스윕 원 대 보스 원)으로 보스 후보를 하나 더해 거리 순으로 정렬한다. 이후 규칙은 지금과 같다(관통 횟수, 같은 대상은 한 번, 마지막 명중에서 멈춤). 보스 후보에는 투사체의 "이미 맞힌 목록"이 보스 식별자를 포함하므로 보스를 두 번 맞히지 않는다.
- `ProjectileSim.Step(dt, mobs)`에 보스 인자를 추가한다(`IBossTarget` 인터페이스: 살아 있음, 위치, 반지름, 피해 주기). 기본값이 없으면 지금과 같이 동작한다.

### 5. 스킬은 `SkillContext`에 보스를 더해 같은 효과에서 함께 맞힌다
`SkillContext.Boss`(`IBossTarget`)를 두고 `AreaDamage`는 반경 안이면, `Beam`은 선과 폭 안이면 보스에도 피해를 준다. `Volley`는 평범한 투사체라 4번에서 처리된다. `TimeStop`, `Push`, `Heal`, `Barrier`는 보스를 건드리지 않는다(스펙). 보스에게 준 피해로 보스가 쓰러지면 승패 판정이 그 틱에 보는 상태로 반영된다(6번).

### 6. 승패 규칙은 `MatchSim`(순수 C#)이 한 곳에서 정한다
`MatchSim`은 매 틱 `Step(dt, 보스가 있는가, 보스가 쓰러졌는가, 살아 있는 생존자 수, 보스 연결 여부)`를 받아 남은 시간을 줄이고 결과를 낸다. 우선순위는 고정이다: **(1) 보스 쓰러짐 → 생존자 승, (2) 보스 이탈 → 생존자 승, (3) 생존자 0명 → 보스 승, (4) 시간 종료 → 보스 승**. 한 번 결과가 나면 바뀌지 않는다. 보스가 없는 판(연습)은 시간이 없고 결과도 내지 않는다(`Enabled = false`). 생존자가 한 명도 없이 시작한 판은 시작할 수 없으므로(대기방 규칙) 이 규칙이 시작 직후에 잘못 발동하지 않는다.
- 대안: `CombatServer` 안에 승패를 직접 쓰기 → 우선순위와 경계(같은 틱, 이탈, 연습)를 네트워크 없이 시험할 수 없다. 채택하지 않았다.

### 7. 방 상태에 결과(Finished)를 더하고 진행 정지는 한 스위치로 한다
`RoomPhase`에 `Finished = 2`를 더한다. `LobbySim`은 `Finish()`로 진행 → 결과로 바꾸고 결과 상태에서는 시작, 선택, 접속을 거절한다. `TryEndMatch`는 진행과 결과 모두에서 허용한다. `RoleTable`이 `MatchSim`의 결과를 읽어 `Finish()`를 부르고, 결과 값(승자, 이유, 남은 시간)을 `NetworkVariable`로 복제한다.
- **정지 스위치**: `RoleTable.MatchRunning`(서버 전용 정적 속성, `Phase == Playing`)을 `MobServer`, `CombatServer`, `GrowthServer`, `PlayerAvatar`의 `FixedUpdate`와 입력 경로 맨 앞에서 검사한다. 지금 각 컴포넌트가 가진 `running`은 서버가 켜졌는지만 뜻해서, 판이 끝난 뒤 멈추려면 이 검사가 필요하다. 이벤트 발행(`mobs.FlushEvents`, `combat.Publish`)과 복제 쓰기는 정지 시에도 마지막 값을 한 번 쓰고 멈춘다.
- 소유자 쪽 입력(`PlayerCombat`, `PlayerGrowth`)은 `Phase != Playing`이면 서버로 보내지 않는다. 서버가 어차피 무시하지만 클라이언트 표시(발사 섬광 등)도 멈춘다.
- 대안: 시간 배율을 0으로(`Time.timeScale`) → 네트워크 틱, 보간, UI까지 멈춰 결과 화면과 호스트 버튼이 죽는다. 채택하지 않았다.

### 8. 결과, 시간, 보스 체력의 복제
`RoleTable`에 `NetworkVariable`을 더한다: 남은 시간(`ushort`, 초 단위 올림, 서버만 쓰고 값이 바뀔 때만 보내므로 초당 1회), 결과(`byte`: 없음, 생존자 승, 보스 승), 이유(`byte`). 보스 체력은 보스 `PlayerCombat`의 기존 체력 `NetworkVariable`을 그대로 쓴다(보스도 `ServerWrite`로 채운다). 모든 클라이언트가 이 값으로 위쪽 막대와 결과 화면을 그린다.

### 9. 보스 접촉 피해는 `SurvivorSim`에 보스 인자로 더한다
`SurvivorSim.Step(dt, bodies, mobs, boss)`가 몹 접촉에 더해 보스(살아 있고 반경 안)의 접촉 피해(보스 정의의 값)를 준다. 몹의 접촉 검사에 있는 "몹이 멈춰 있으면 피해 없음"은 보스에는 적용하지 않는다. 피해 뒤 무적 시간은 한 생존자에게 하나(몹이든 보스든)라서 같은 틱에 둘이 닿아도 한 번만 다친다.

### 10. 보스 화면
- 위쪽 가운데에 모든 사람에게 남은 시간과 보스 체력 막대(`MatchHud`, IMGUI). 보스 플레이어는 추가로 아래쪽에 생존자 요약(캐릭터 이름, 체력 막대, 쓰러짐 표시)을 본다. 이 값은 이미 모두에게 복제되는 `PlayerCombat` 체력과 `RoleTable`의 슬롯 캐릭터에서 만든다.
- 결과 화면: 화면 가운데에 승패, 이유, 남은 시간. 호스트에게는 "대기방으로 돌아가기" 버튼(기존 버튼을 결과 상태에서도 보이게), 나머지는 "호스트가 돌아가기를 기다리는 중".
- 보스 캐릭터 위에는 보스 체력 막대를 그린다(생존자 막대와 같은 방식, 더 크게). 쓰러지면 회색.

### 11. 개발 인자
`-bsBossHealth <n>`(호스트: 보스 최대 체력), `-bsMatchSeconds <초>`(호스트: 제한 시간), `-bsBossChase`(보스 플레이어가 가장 가까운 생존자 방향으로 자동 이동, 승패 시험에서 보스가 생존자를 때리게). 서버는 승패와 이유를 `[BS] match ...` 로그로 남긴다.

## Risks / Trade-offs

- [새 방 상태가 기존 `RoomPhase` 사용처를 깨뜨릴 수 있다. `Phase == Playing`을 가정한 곳이 많다] → 모든 사용처를 확인해, "대기가 아님"과 "진행 중"을 구분해서 쓴다(몹과 전투 정지는 진행 중만, 캐릭터 존재는 진행과 결과). 대기방 흐름과 둘째 판 시험을 새 상태 포함으로 다시 돌린다.
- [`ushort.MaxValue`를 보스 식별자로 예약하는 것이 몹 식별자 순환과 부딪친다] → `NextFreeId`가 그 값을 건너뛰게 하고, 순환 시험을 둔다. 클라이언트의 `MobInterpolator`에 보스 식별자로 몹이 생기지 않는지도 확인한다.
- [보스 체력 6000이 너무 높거나 낮다] → 가정값이고 개발 인자로 바꿀 수 있다. 플레이로 조절한다.
- [결과 상태에서 서버가 멈추는데 `FixedUpdate`가 일부는 계속 돌면 몹이 움직이거나 투사체가 날아간다] → 정지 스위치를 모든 서버 컴포넌트의 맨 앞에 두고, 결과 상태 시험에서 몹 위치 합계와 투사체 수가 변하지 않는 것을 확인한다.
- [같은 틱에 보스가 쓰러지고 마지막 생존자가 쓰러지는 경계] → `MatchSim`이 우선순위로 정하고 EditMode로 시험한다.
- [보스가 연습이 아닌 판에서만 승패가 있다는 규칙이 시험 절차를 바꾼다] → 기존 시험 명령은 보스 없이 돌려서 그대로 두고, 보스 시험을 새로 둔다.
- [생존자가 한 명뿐이고 보스가 있는 판이 시작 직후 끝난다] → 시작 조건에 생존자가 1명 이상이 있으므로 시작 시점은 안전하다. 그 생존자가 곧 쓰러지면 정상적으로 보스 승이다.
- [보스 접촉 피해와 몹 접촉 피해가 같은 생존자에게 겹치는 경계] → 무적 시간이 하나라 한 번만 맞는 것을 시험으로 확인한다.

## Migration Plan

- 저장 데이터와 서버가 없어 마이그레이션은 없다. 씬 설정 메뉴를 다시 실행할 필요는 없다(새 컴포넌트는 `MatchHud` 하나이며, 필요하면 `NetworkSceneSetup`이 `Mobs` 오브젝트에 더한다. 그때는 씬 설정 메뉴를 다시 실행한다).
- 되돌리기: 보스 정의의 체력을 매우 크게 하고 제한 시간을 아주 길게 하면 이전의 "끝나지 않는 판"과 거의 같다. 보스가 없는 판은 이전과 완전히 같다.

## Open Questions

- 보스 체력과 제한 시간의 균형은 플레이로 정한다(가정값 6000, 300초).
- 결과 화면에서 호스트만 돌아가기를 누를 수 있는 것이 불편하면, 일정 시간 뒤 자동으로 대기방에 돌아가게 할지 정한다. 바꿔도 스펙 한 문장이다.
