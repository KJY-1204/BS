# Tasks

## 1. 장치 데이터와 몹 시뮬레이션 (boss-devices)

- [x] 1.1 `MobKinds`에 장치 종류(5번)를 더하고(체력 배수 큼, 속도 0, 접촉 배수 0, 몸 크기와 색은 어느 몹 종류와도 다르게), 보스가 고를 수 있는 종류 수를 `SummonableCount`(5)로 나눠 숫자 키, 소환 HUD 줄, 소환 통계 로그, `Summon`의 없는 종류 검사가 그것을 쓰게 한다. 장치의 값(생성 간격, 한 번에 만드는 마리수, 고리 거리, 수명, 동시 상한, 에너지 비용, 설치 쿨타임, 안전 거리, 장치 경험치)은 한 데이터 묶음(`DeviceConfig`)에 둔다. EditMode 테스트로 장치가 다섯 몹 종류와 이름, 색, 크기가 다른 것, 소환 가능한 종류 수가 5로 그대로인 것, 없는 종류 소환 거부가 장치 번호에서도 거부되는 것을 확인한다
- [x] 1.2 `MobSim`에서 장치를 몹과 다르게 다루는 곳을 막는다: 따라가기(속도 0), `Separate`(밀리지도 밀지도 않음), `Push`, 접촉 피해(`MaxContactMultipleWithin`이 장치를 건너뜀), 명령 적용(`ApplyOrderToSummoned`, `SetTarget`), 소환된 몹 수 집계, 원거리/폭발 행동. EditMode 테스트로 장치가 위치를 유지하는 것, 바람(`Push`)에 안 밀리는 것, 접촉해도 생존자가 안 다치고 막히지 않는 것, 명령에 영향이 없는 것, 자동 생성 목표 수(`AutoCount`)와 숫자 키 집계에 안 섞이는 것을 확인한다
- [x] 1.3 `MobSim`에 장치의 생성 간격 타이머와 남은 수명(새 배열)을 더하고, `Step`에서 시간 정지로 일찍 끝나기 전에 장치 단계를 돌린다(생성, 수명 만료). 생성은 보스 소환과 같은 고리 위치 고르기(안전 거리, 아레나 안)를 공유하는 도우미로 하고, 상한이 남기는 만큼만 소환된 기본 몹을 만들며 소환 기운은 안 쓴다. 서 있는 명령(`ApplyOrderToSummoned`로 받은 마지막 명령)을 장치가 만든 몹에도 적용한다. 수명이 끝나면 `Remove`로 없애고 죽음 기록은 남기지 않는다. EditMode 테스트로 간격마다 생성, 생존자가 고리에 서 있을 때 다른 자리나 적게, 상한이 낮을 때 일부만/전혀 안 만드는 것, 명령이 만든 몹에 적용되는 것, 시간 정지 중에도 계속 만드는 것, 수명 만료에 사라지고 더 안 만드는 것, 만료는 죽음 기록이 없는 것을 확인한다
- [x] 1.4 피해 경로를 확인한다: 투사체(관통 포함), 범위 폭발, 광선, 나이프가 장치를 몹처럼 때리고, 보스의 투사체와 보스 스킬이 장치를 안 때리고, 체력이 0이 되면 사라지며 죽음 기록이 남는 것. 필요한 곳(`ProjectileSim`/`SkillSim`/`MobSim`의 표적 모음)만 고친다. EditMode 테스트로 한 발 맞음과 투사체 멈춤, 관통하는 투사체가 장치를 한 번만 맞히고 계속 날아가는 것, 폭발/광선/나이프 피해, 시간 정지/바람/치유/방벽이 영향 없는 것, 보스의 투사체와 스킬이 장치를 무시하는 것, 파괴되면 생성이 멈추는 것을 확인한다

## 2. 설치 규칙과 경험치 (boss-devices, survivor-leveling)

- [x] 2.1 `SummonSim.PlaceDevice`를 만든다(보스가 아니면 무시, 판이 안 돌거나 보스가 쓰러졌으면 불가, 설치 쿨타임, 동시 상한, 몹 상한, 에너지, 보스 위치 근처 생존자 안전 거리). 에너지는 소환과 공유하고 쿨타임은 소환과 따로 둔다. 결과 값(상한 도달, 생존자가 너무 가까움)을 `SummonResult`에 더한다. EditMode 테스트로 성공하면 에너지가 비용만큼 줄고 쿨타임이 시작되는 것, 각 거부(보스 아님, 판 아님, 보스 쓰러짐, 쿨타임, 상한, 몹 상한, 에너지 부족, 생존자가 너무 가까움)에서 에너지와 장치가 그대로인 것, 소환 직후에도 설치되는 것, 파괴/만료 뒤 다시 설치되는 것, 새 판이 장치 없이 시작하는 것을 확인한다
- [x] 2.2 죽음 기록이 시작 위치와 함께 기본 경험치량을 싣도록 바꾸고(몹은 `XpPerKill`, 장치는 `XpPerDevice`), `LevelingSim.AwardKill`이 그 양에서 경험치 패시브를 적용해 나눠 주게 한다. EditMode 테스트로 장치를 부수면 몹보다 많은 양이 나눔 거리 안의 산 생존자 모두에게 가는 것, 경험치 패시브가 있는 쪽만 늘어나는 것, 거리 밖/쓰러진 생존자/보스는 못 받는 것, 만료와 판 끝은 경험치가 없는 것, 장치가 만든 몹은 보통 몹과 같은 양인 것, 기존 몹 경험치 시험이 그대로 통과하는 것을 확인한다

## 3. 요청과 화면 (boss-devices)

- [x] 3.1 `PlayerSummon`에 `PlaceDeviceRpc`(서버로)와 R 키 입력(눌린 순간 한 번)을 더하고, `SummonServer`가 요청을 `PlaceDevice`로 넘겨 결과를 기존 `ResultRpc`로 보스에게 돌려준다. 보스 전용 정보(서 있는 장치 수와 상한, 설치 쿨타임)를 이미 보스에게만 가는 에너지 정보에 필드로 더한다(생존자에게는 안 간다). `DevArgs`에 자동 설치 개발 인자(`-bsAutoDevice`)를 더한다. EditMode 테스트로 보스 아닌 요청이 무시되는 것, 결과 코드가 보스에게만 가는 것, 생존자 쪽 상태에 장치 정보가 없는 것을 확인한다
- [x] 3.2 `SummonHud`에 R 키 힌트, 서 있는 장치 수/상한, 설치 쿨타임("준비" 또는 남은 초)을 더하고 거부될 때 짧은 표시를 한다(보스 화면에만). `MobView`가 장치를 장치 종류의 모양과 크기로 그리고, `CombatView`가 장치 위에 항상 보이는 체력 막대를 그린다(생성 때는 가득, 맞을 때마다 보내는 체력 비율로 갱신, 사라지면 정리). 늦게 들어온 사람은 가득 찬 막대로 시작한다. 시험은 EditMode로 장치 종류에서 그릴 값(색, 반지름, 막대 표시 여부)을 구하는 순수 함수에 대해 하고, 그림은 4.2에서 눈으로 확인한다

## 4. 통합 시험과 문서 (전체)

- [x] 4.1 (통합) 직접 IP 다중 프로세스(보스 호스트 + 생존자 3명, 자동 설치와 자동 사격 개발 인자)로, 서버 로그에 설치/생성/파괴/만료와 에너지 변화가 나오고, 서버와 모든 클라이언트의 몹 목록과 위치(장치 포함)가 일치하고, 생존자가 장치를 부쉈을 때 경험치가 오르고, 늦게 들어온 클라이언트에 서 있는 장치가 보이는 것을 확인한다. 보스가 아닌 사람의 설치 요청 거부는 통합에서 보내는 수단이 없어 EditMode(2.1, 3.1)로 확인한다
- [x] 4.2 (화면 확인) 개발 빌드를 창 모드로 띄워 장치의 모양과 크기, 체력 막대, 보스 화면의 R 키 힌트/장치 수/쿨타임, 생존자 화면에 보스 정보가 없는 것, 장치가 사라질 때를 눈으로 확인한다. 어긋나거나 잘리면 그 표시만 고친다
- [x] 4.3 (통합, 수동) 실제 Relay로 보스(호스트)와 생존자 3명이 한 판을 끝까지 하며 장치를 설치/파괴하고, 몹 트래픽(클라이언트당 50 KB/s 이하), 전투 트래픽(10 KB/s 이하), 서버 틱 시간을 장치가 상한만큼 서 있을 때 측정한다
- [x] 4.4 기존 EditMode 테스트 전체와 이전 통합 로그 비교(몹 위치, 전투 이벤트, 부활, 성장 선택, 대기방 흐름, 캐릭터별 공격과 스킬, 전용 패시브, 스킬 배율, 보스 승패, 소환과 명령, 보스 공격과 스킬, 몹 종류와 행동, 보스 종류)를 다시 돌려 회귀가 없는 것을 확인하고, README(장치 설명, R 키, 개발 인자 `-bsAutoDevice`, 테스트 수, 측정 결과, 알려진 한계: 수치는 가정값이고 밸런스 조정 단계에서 맞춘다, 늦게 들어온 사람의 장치 체력 막대)를 갱신한 뒤 문서의 명령을 그대로 따라 해서 재현되는지 확인한다
