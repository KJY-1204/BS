# Tasks

## 1. 진화 데이터와 선택 규칙 (skill-evolutions, skill-tree-selection, character-skills)

- [x] 1.1 `SkillDef`에 `EvolvesFrom`과 `ExclusiveWith`를 더하고, `SkillCatalog.IsAvailable`이 `ExclusiveWith`의 랭크가 0보다 크면 제안하지 않게 한다. `ForSlot`은 진화 정의를 건너뛰어 기본 스킬만 돌려주게 하고, `ActiveForSlot(slot, 캐릭터, 랭크)`(배운 진화가 있으면 그것, 없으면 기본 스킬)를 더한다. EditMode 테스트로 `ForSlot`이 진화 id를 절대 주지 않는 것, `ActiveForSlot`이 진화를 안 배웠으면 기본 스킬을 주고 배웠으면(기본 랭크와 무관하게) 진화를 주는 것, 배제가 동작하는 것(한쪽을 배우면 다른 쪽과 자기 자신이 안 나옴)을 확인한다
- [x] 1.2 설계의 표대로 진화 8개(id 33~40, 레이무/마리사/사쿠야/사나에의 Q마다 둘)를 데이터로 정의한다(활성, 기본 스킬의 슬롯과 캐릭터, 랭크 1, 기본 스킬 최대 랭크가 선행 조건, 서로 배제, 이름과 득실을 말하는 설명). EditMode 테스트로 id가 모두 다르고 42 이하인 것, 랭크 포장이 33~40에서도 왕복하는 것(경계 포함), 각 진화가 같은 캐릭터의 Q 스킬과 같은 효과 종류인 것, 기본 스킬의 최대 랭크에서 비용/쿨타임/효과 값 중 하나 이상이 더 나쁜 것(우위 없음), 같은 스킬의 두 진화가 서로 다른 것, R 스킬의 값이 기본 Q/E보다 큰 규칙이 그대로 지켜지는 것을 확인한다
- [x] 1.3 선택지 규칙을 확인한다. EditMode 테스트로 Q가 최대 랭크 미만이면 진화가 절대 제안되지 않는 것, 최대 랭크이면 둘 다 후보가 되고 고르면 랭크 1이 되는 것, 하나를 고른 뒤에는 두 진화 모두 다시 제안되지 않는 것(레벨 20까지), 다른 캐릭터의 진화가 제안되지 않는 것, 진화를 고른 뒤에도 R 스킬의 선행 조건(Q 랭크 2)이 참인 것을 확인한다. 개수와 슬롯을 세는 기존 테스트(캐릭터당 활성 스킬 3개, 한 캐릭터의 두 스킬이 슬롯을 나눠 쓰지 않음, 배울 수 있는 랭크 합)가 진화를 구분하도록 고치고 전체 EditMode 테스트가 통과하는 것을 확인한다

## 2. 서버의 발동 (skill-evolutions)

- [x] 2.1 `SkillSim.TryActivate`가 `ActiveForSlot`으로 고른 스킬을 발동하게 한다(비용, 쿨타임, 효과 값, 패시브 적용은 고른 스킬의 것). EditMode 테스트로 진화를 배운 생존자가 Q를 누르면 진화가 자기 마나 소모와 쿨타임과 값으로 발동하고 기본 스킬은 발동하지 않는 것, 활성화 결과에 진화 id가 실리는 것, 여덟 진화가 각각 원래 효과 종류대로 동작하는 것(레이무: 반경과 피해 차이로 몹이 맞고 안 맞음, 마리사: 길이/폭에 따라 맞고 안 맞음, 사쿠야: 정지 시간, 사나에: 반경과 회복량), 캐릭터의 패시브(비용, 피해, 쿨타임, 범위, 지속)가 진화에도 적용되는 것, 거절 규칙(쿨타임, 마나 부족, 쓰러짐)이 그대로인 것, 진화를 배워도 E와 R의 쿨타임이 따로 도는 것을 확인한다
- [x] 2.2 클라이언트가 서버가 판정한 대로 그리는지 확인한다. EditMode 테스트로 `TheClientDrawsExactlyWhatTheServerJudged`류의 검사(활성 스킬의 반경/길이/폭/지속이 클라이언트의 크기 계산과 일치)가 진화 여덟 개에도 통과하는 것, 스킬 이벤트가 진화 id를 실어 부호화/해석 왕복이 되는 것을 확인한다
