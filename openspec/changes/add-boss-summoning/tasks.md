# Tasks

## 1. 몹 쪽 변경 (mob-simulation)

- [x] 1.1 `MobSim`이 몹의 출처(자동 = 종류 0, 소환 = 종류 1)를 `IsSummoned`/`AutoCount`/`SummonedCount`로 알려 주고, 개수가 스폰/제거/`Clear`에서 맞게 유지되며(제거의 마지막 항목 옮기기 포함), 자동 스폰이 총 몹 수가 아니라 자동 몹 개수로 `TargetCount`와 비교하고, 하드 상한은 둘이 나눠 쓰는 것을 EditMode 테스트로 확인한다. 기존 몹 테스트가 그대로 통과한다
- [x] 1.2 `MobSim`의 위치 덮어쓰기가 도착 반경(0.4) 안에서 풀려 그 몹이 가장 가까운 생존자를 쫓게 하고(생존자 덮어쓰기와 해제와 나감 처리는 그대로), 지점이 아레나 밖이면 안쪽으로 당겨지며, 소환 몹 전체에 명령을 한 번에 적용하는 함수(`ApplyOrderToSummoned`: 생존자/지점/해제)가 자동 몹을 건드리지 않는 것, 덮어쓴 생존자가 쓰러지면 가장 가까운 생존자를 쫓고 되살아나면 돌아오는 것을 EditMode 테스트로 확인한다
- [x] 1.3 자동 스폰 값 묶음(`MobConfig`에 보스 판용 스폰율 0.5와 자동 목표 20, 연습 판은 이전 2와 80)을 두고 `MobServer`가 판 시작 때 보스 판인지에 따라 고르게 한다(`-bsMobTarget`은 자동 목표를 계속 덮어씀). 보스 판은 느리고 작게, 연습 판은 이전과 같이 차는 것을 EditMode 테스트(`MobSim`을 값만 바꿔 돌림)와 에디터 `eval`로 확인한다

## 2. 소환 규칙 (boss-summoning, boss-orders)

- [x] 2.1 순수 C# `SummonSim`과 설정 객체(최대 100, 시작 50, 충전 5/초, 몹당 5, 무리 4, 쿨타임 0.6, 고리 1.5~3.0, 안전 거리 2.5, 지정 거리 2.0)를 만든다: 기운 충전과 상한, 시작값, 쿨타임, 요청이 오면 한 틱에 처리, 기운이 모자라면 살 수 있는 만큼만 만들고 그만큼만 차감, 한 마리도 못 사면 거절하고 차감 없음, 하드 상한에서 거절과 일부만 만들기, 보스가 쓰러졌거나 진행 중이 아니면 거절, 개별 결과(성공/일부/기운 부족/쿨타임/가득 참/불가)를 EditMode 테스트로 확인한다
- [x] 2.2 소환 위치: 보스를 중심으로 한 고리와 아레나 안, 살아 있는 생존자와 안전 거리 이상, 모든 위치가 막히면 만들지 않음, 아레나 가장자리에서도 안쪽으로 당겨져 만들어지는 것과 소환 몹이 종류 1인 것을 EditMode 테스트로 확인한다
- [x] 2.3 명령 상태: 서 있는 명령 하나(없음/생존자/지점), 포인터 좌표에서 지정 거리 안의 가장 가까운 살아 있는 생존자를 고르고 없으면 지점 명령, 지점이 아레나 안으로 당겨지는 것, 새 명령이 이전 명령을 대체하는 것, 해제, 새로 소환한 몹이 서 있는 명령을 받는 것, 대상 생존자가 나가면 명령이 지워지는 것, 보스가 아닌 사람의 명령이 무시되는 것, 판 시작 시 초기화를 EditMode 테스트로 확인한다

## 3. 서버와 복제 (boss-summoning, boss-orders)

- [x] 3.1 새 `SummonServer`(MonoBehaviour)를 만든다: `FixedUpdate`에서 `RoleTable.MatchRunning`이고 보스가 있는 판일 때만 `SummonSim`을 돌리고, 보스 위치, 생존자 목록, 보스 쓰러짐을 넘기며, 소환 직후 `MobServer.FlushEvents`를 불러 스폰 이벤트를 같은 틱에 보낸다. 판이 시작될 때와 `ResetMatch`, 서버 종료 때 초기화하고, `RoleTable`이 판 시작 때 보스 판 여부를 `MobServer`와 `SummonServer`에 알린다. 에디터 `eval`로 소환, 거절, 정지, 초기화를 확인한다
- [x] 3.2 새 `PlayerSummon`(NetworkBehaviour, Player 프리팹)을 만든다: 소유자만 읽는 `NetworkVariable`(기운, 최대 기운, 명령 종류, 명령 대상 역할, 명령 지점)을 서버가 쓰고, 보스 소유자의 입력(소환 = 왼쪽 클릭/Space, 명령 = 오른쪽 클릭의 세계 좌표, 해제 = C)을 `[Rpc(SendTo.Server)]`로 보내며(초당 20회 이하), 서버는 보낸 사람이 보스인지 확인한다. 생존자의 `PlayerSummon`은 입력을 읽지 않고 값을 받지 않는다. `NetworkSceneSetup`에 연결한다. 에디터 `eval`로 비보스 요청이 무시되고 소유자만 값을 읽는 것을 확인한다
- [x] 3.3 소환 거절을 보스 소유자에게 짧은 알림으로 돌려보내고(기운 부족/쿨타임 등), 보스 연결 끊김, 판 종료, 대기방 복귀에서 소환과 명령이 정리되고 둘째 판이 처음과 같게 시작하는 것을 에디터 `eval`로 확인한다

## 5. 개발 인자와 통합 시험 (전체)

- [x] 5.1 개발 인자를 만든다: `-bsAutoSummon <초>`(보스 소유자가 그 간격으로 소환), `-bsAutoOrderPlayer <역할> <초>`(그 초에 해당 역할 생존자의 현재 위치를 포인터로 보내 생존자 명령), `-bsAutoOrderPoint <x> <y> <초>`, `-bsAutoClear <초>`, `-bsSummonEnergy <n>`(최대와 시작을 n으로)와 서버의 `[BS] summon:`/`order:` 로그(기운, 결과, 명령 변화), 5초 통계에 자동/소환 몹 수를 더한다. 로그가 나오는 것을 확인한다
- [x] 5.2 (통합) 보스 + 생존자 3명(대기방을 거침): 자동 소환으로 소환 몹이 생기고 기운이 줄고 다시 차는 것, 기운이 모자랄 때 일부만/거절되는 것, 자동 스폰이 보스 판에서 이전보다 약한 것을 서버 로그로 확인하고, `tools/compare_mobdumps.py`로 몹 위치가 서버와 모든 클라이언트에서 일치하며 임시 몹이 없는 것, `tools/compare_combat.py`로 전투 이벤트가 일치하는 것을 확인한다
- [x] 5.3 (통합) 명령: 생존자 명령 뒤 소환 몹이 지정한 생존자 쪽으로만 모이는 것(서버 로그의 거리 통계), 그 생존자가 쓰러지면 가장 가까운 생존자를 쫓고 되살아나면 돌아오는 것(`-bsDevKill`, `-bsDevMeet`), 지점 명령으로 몹이 지점에 모였다가 풀리는 것, 새로 소환한 몹이 서 있는 명령을 받는 것, 해제, 비보스 클라이언트의 요청이 무시되는 것, 생존자 클라이언트 로그에 기운/명령 값이 없는 것을 확인한다
- [x] 5.4 (통합) 정지와 정리: 결과 상태에서 소환/명령이 먹지 않고 기운이 변하지 않는 것, 대기방 복귀 뒤 둘째 판의 기운과 명령이 처음과 같은 것, 연습 판(보스 없음)의 자동 스폰이 이전 값 그대로인 것을 로그로 확인한다
- [x] 5.5 (통합, 수동) 실제 Relay로 보스(호스트) + 생존자 3명이 소환과 명령을 쓰며 한 판을 끝까지(결과, 복귀, 둘째 판) 하는 흐름과 전투 트래픽(클라이언트당 10 KB/s 이하), 몹 트래픽(50 KB/s 이하), 서버 틱 시간을 측정한다
- [x] 5.6 기존 EditMode 테스트 전체와 이전 통합 로그 비교(몹 위치, 전투 이벤트, 부활, 성장 선택, 대기방 흐름, 캐릭터별 공격과 스킬, 보스 승패)를 다시 돌려 회귀가 없는 것을 확인하고, README(소환과 명령 설명, 자원/키 표, 자동 스폰 값 변화, 개발 인자, 테스트 수, 측정 결과, 알려진 한계)를 갱신한 뒤 문서의 명령을 그대로 따라 해서 재현되는지 확인한다
